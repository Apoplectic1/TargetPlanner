# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Windows Forms desktop tool for astrophotography planning, plotting target altitude over time with multi-target overlay. Targets load from two on-disk formats — NINA sequence files (`.json`) and `.xisf` images — recursively scanned by `Targets/TargetScanner.cs`, which groups each target's files (capture frames, mosaic panels) and resolves one `Target` at the spherical centroid of the group (`Targets/SkyCentroid.cs`). **User-facing behaviour, defaults, and chart UX live in [README.md](README.md)** — this file focuses on code organisation, conventions, and gotchas for a coding agent. Settings-resolved target roots: `MainForm.NinaTargetsRootPath` / `MainForm.ImageLibraryRootPath`. Single render entry point: `Button_Graph_Click` → `mCoordinator.ApplyImmediateAsync(SnapshotCurrent(targets))`. On startup the image library auto-loads (async, `GetImageLibraryTargets`); the post-load handler seeds `mSelection.SelectedSingle` to the first sorted target.

**Architecture / refactor terms** (deep detail in [ARCHITECTURE.md](ARCHITECTURE.md)):
- **VM** — view-model. Specifically `TargetSelection` (`State/TargetSelection.cs`).
- **SoC refactor** — three-phase selection/cache/render decoupling + follow-on orchestration-layer refactor + 2026-05-17 pipeline collapse (cache `EnsureAsync` as single staleness gate). See ARCHITECTURE.md §Cache store + §Orchestration.
- **ChartContext** — immutable record snapshot in `State/ChartContext.cs` of chart-pipeline inputs (`Location`, `Targets`, `Policy`, `Observation`, `ActiveArea`, `TargetColors`, `DayMode`) + derived `Hdm` keying the fits cache. `Observation` is `Astronomy.Core.Time.ObservationMoment` carrying per-session `(Utc, Zone)`.
- **PlanningPolicy** — immutable record in `State/PlanningPolicy.cs` aggregating planning inputs (`TargetFloorDeg`, `MinDuration`, `MoonProfile`, `FilterCenterNm`, `LocalHorizon`). When both a polyline `.hrz` AND a non-zero floor exist, `SnapshotCurrent` composes via `MaxOfHorizonProfile(polyline, ScalarHorizonProfile(floor))`.
- **PlanningPreferences** — immutable record in `State/PlanningPreferences.cs` carrying `(TargetFloorDeg, MinDuration)`. Per-site subset of `PlanningPolicy`; persisted on `NamedSite.Preferences`. Spinner handlers mirror back via `PersistPlanningPreferencesToActiveSite()` so close-time save persists latest values rather than the stale Preferences DTO that was set at site-pick time.
- **ChartEvaluation** — single-field record in `State/ChartEvaluation.cs` returned by `IChartCacheStore.EnsureAsync`. Carries just `BrightnessInputsChanged`; consumed only by the coordinator's post-apply hook to gate `PushSkyKSInputs(ctx)`.
- **ChartCoordinator** — thin funnel in `State/ChartCoordinator.cs`. Pipeline: generation bump → compute `dayKey` → `await mCache.EnsureAsync(ctx, dayKey)` → generation guard → `mRenderActiveArea(ctx)` → `mPostApplyHook(ctx, eval)`. 150 ms debounce; `mGeneration` supersedence. Every UI handler reduces to `mCoordinator.Apply(SnapshotCurrent(...))`; `LastAppliedTargets` is the canonical active set for re-snapshot callers.
- **EnsureAsync** — `IChartCacheStore.EnsureAsync(ctx, dayKey)` is the single pre-render pipeline. Diffs `ctx` against `mLastEnsureCtx` + date axis, runs the matching `Prepare*Async` paths, returns a populated `ChartEvaluation`. See ARCHITECTURE.md §Cache store.

**Domain terms in chart code** (user-facing definitions in [README.md](README.md#domain-terms)):
- **HD Overlay** — Day-chart click-toggled best-window step function. `LC2 OverlayController` (sibling to `AltitudeSubChart_Day`) owns the state machine; right-click `ToggleAll` enters "global mode" with `mGlobalOptOuts` per-target carve-outs and a sticky fast-path for identical-pixel re-toggle. See ARCHITECTURE.md §Charting.
- **D-hour window** — `Astronomy.Core.Session.BestSession.For`. `PlanningPreferences.MinDuration` is the floor.
- **Ceiling / Floor / Symmetric** — three `LineSeries<ObservablePoint>` per target on `AltitudeSubChart_Sessions`. ONE legend item per target toggles all three's `IsVisible`; `BestSession.ResolveCandidates` resolves visibility ∩ moon-clear once per night so `PlaceBest` (Ceiling/Floor) and `PlaceCentered` (Symmetric) see identical inputs.

## Build / run

- Solution `TargetPlanner.sln` contains **one project authored here** plus two sibling-library projects listed for Solution Explorer visibility:

The Win10 2004 contract version is needed because `SkiaSharp.Views.WindowsForms 3.119.0` (transitive via LiveCharts2) only ships modern-.NET assets at `net8.0-windows10.0.19041`. Configurations: `Debug|AnyCPU`, `Release|AnyCPU`, `Debug|x64`, `Release|x64`.   - `..\Library\Astronomy.Core\Astronomy.Core.csproj` + `..\Library\Astronomy.NINA\Astronomy.NINA.csproj` — **consumed** via csproj `<ProjectReference>`. `..\Library\Astronomy.XISF\` is sln-visible only and flows transitively through NINA.

## Architecture

The codebase is split at the repo boundary: **`Astronomy.Core`** in the sibling `Library\` repo provides pure UI-free math + POCOs; **`TargetPlanner`** (this repo) is the WinForms chart/host/UI consuming Core via `ProjectReference`. Two newer sibling libraries (`Astronomy.XISF`, `Astronomy.NINA`) flow in transitively. TP has been through a three-phase SoC refactor + follow-on orchestration-layer refactor + 2026-05-17 pipeline collapse — chart construction decoupled from cache, cache from selection, selection from UI, and an explicit **`ChartCoordinator`** funnels every UI handler's downstream effects through one diff-and-dispatch pipeline. Shape:

- **Selection state** in `State/TargetSelection.cs` — observable VM owning `KnownTargets`, `SelectedSingle`, `Checked`. UI controls are views under a `mUpdatingUiFromVm` echo guard. **Button_Graph and the checked-set are independent views** — clicking Button_Graph after checking targets renders just the combo target while checkboxes stay ticked; the next checkbox toggle re-renders the full checked set. Add/Remove buttons mutate `KnownTargets` directly, persisting locally-typed targets to `%AppData%\TargetPlanner\local-targets.json` via `Settings/LocalTargetStore.cs`.
- **Cache state** in `Caches/ChartCacheStore.cs` — single-writer four-axis cache: `(Location, Target)` yearDays, `(Target, HdmKey)` fits (per-target `TargetFitEntry` carries both per-night `Nights[i]` array and a single-night `Tonight` slot — single source of truth across all four charts), `(Target, DayWindowKey)` Day per-minute altitudes, and `DayWindowKey → MoonAltitudeEntry` per-minute moon altitudes (target-independent singleton). Public surface is `EnsureAsync(ctx, dayKey) → ChartEvaluation` — single seam where staleness reasoning + downstream Prepare calls happen. Sub-charts read via sync `Get*OrNull`.
- **Rendering** in `Charts/` — four `IAltitudeSubChart` implementations (Day / Sky / Year / Sessions) on LiveCharts2 v2.1.0-dev-365. MS Charts (`System.Windows.Forms.DataVisualization`) is gone. Sub-charts are render-only and read everything from the cache; zero UI-thread `BestSession.For` / `AltAz.At` / `AstroUtil.GetMoonAltitude` calls in any cache-warm path (defensive inline fallbacks exist in moon paths for cache-miss races, log WARN if they fire). Sub-charts always Render (Phase 7's per-sub-chart short-circuit was shipped and reverted on LC2 paint instability across hidden→visible `Control` transitions).
- **Orchestration** in `State/ChartContext.cs` + `State/ChartCoordinator.cs` — immutable input snapshot threaded through the coordinator. UI handlers reduce to `mCoordinator.Apply(SnapshotCurrent(...))` (debounced 150 ms) or `ApplyImmediateAsync(...)` (no-debounce, awaitable, for combo location pick + `RunGraphBuildAsync` + `ResetForLocationChange`). The cache's `EnsureAsync` is the single seam — pre-2026-05-17 the coordinator owned a per-area diff table + 3-way `Render` / `RefreshVisibility` / `ShowOnly` dispatch, all collapsed in the pipeline-collapse refactor. `MainForm.RenderArea` does `sc.Render(ctx, mCache)` → `ShowOnlyAltitudeChart(sc.Control)` → `sc.Control.Refresh()` — the synchronous Refresh after the `Visible=true` flip is load-bearing for the moon overlay's first paint (LC2's SKControl drops Fill-only `LineSeries` from its paint output without the kick).

**Threading**: UI thread owns form events, VM mutations, coordinator pipeline, render passes, chart paint. Off-thread work is `Task.Run` inside the cache's per-axis builders (per-target year + fit + day, per-Location NightCache + Moon altitudes) — lock-free since the CS-removal. No `CancellationToken` parameters in the cache surface; stale work runs to completion and discards itself at publish via `ReferenceEquals(mLocation, buildLocation)`. Form-lifecycle cancellation is the one CTS (`mFormClosingCts` on MainForm), observed only at the outer `Task.WhenAny(warmupTask, cancelledTask)` boundary in the NINA-load warmup. **Perf budget**: cache pre-population is **2–4 sec for 44 targets** (yearDays) plus a few seconds for fits (was ~17 min pre-CS-removal). Design future cache work against this ceiling.

**Deep architecture detail** (Core surface summary, cache store internals, sub-chart wiring, universal chart-behaviour contract, moon avoidance, K-S sky brightness, MainForm UI flow) lives in [ARCHITECTURE.md](ARCHITECTURE.md). Open it when editing `Charts/`, `Caches/`, `State/`, `Filters/`, or any chart-pipeline path in `Forms/MainForm.cs`.

## Conventions worth knowing before editing

- **RA is decimal hours** (`[0, 24)`) in `Target.RightAscension`. The UI presents D/M/S of arc only for Declination; RA D/M/S are derived hour/minute/second fields. Core's `AltAz` and `TargetGeometry` consume `RightAscension` directly as hours.
- **Signed hemispheres** are a TargetPlanner / Core convention: `Latitude`, `Longitude`, `Declination` are stored as positive magnitudes with a paired `North` / `West` flag. Core helpers that take "signed degrees" (e.g. `TargetGeometry.MeridianAltitude`) expect the caller to resolve the flag — see `AltAz.At` for the canonical resolution idiom.
- **Type-alias usings for Core types.** Files in `TargetPlanner.*` namespaces that reference `Astronomy.Core.Targets.Target` use a `using Target = Astronomy.Core.Targets.Target;` alias at the top. Defensive against a future `TargetPlanner.Target` namespace shadowing the type.
- **Defaults resolve at runtime, two layers deep.** `settings.json` (`%AppData%\TargetPlanner\settings.json`, the single user-state file) → hardcoded C# seed in `PersonalDefaults.BuildSeedSettings()` (factory returning a fresh `AppSettings` with `LastSelectedLocationName`, `NinaTargetsRoot`, 4 NamedSites). `SettingsStore.Load`: missing file → call factory + save + return; present file → deserialise, apply **Pattern C** (fill any null/empty top-level field from the seed — additive-schema migration self-heal), strip any saved "Custom"-named site (sentinel-reserved for `ComboBox_Location`'s free-edit row). `File > Defaults > Edit settings.json` launches the OS editor; `File > Defaults > Clear (factory reset)` wipes settings.json + filters.json + local-targets.json + Logs/ and exits (both paths set `mSuppressFormClosingSave` so the exit-time save doesn't clobber). Boot picks `mAppSettings.LastSelectedLocationName`.
- **`Location.Elevation`** (meters above geoid, default 0) is honored by `MoonSeparation.ObserveAt` (parallax via `MoonPosition.Topocentric`, ~0.5″ per 1000 m) and by `AstroUtil.GetSunRiseAndSet` / `GetMoonRiseAndSet` (refracted horizon dip via `MeeusUtility.HorizonDipDeg`, ~0.26° at 80 m / ~2.93° at 10000 m). Civil/Nautical/Astronomical twilight thresholds (-6/-12/-18) are by convention NOT elevation-corrected — they reference the celestial horizontal plane.
- **Target sources & roots.** Four entry points load targets, each **adding** to the known-target set (duplicates skipped via `TargetIdentity`; `Button_ClearAllTargets` is the only path that empties): (1) **startup** auto-loads the image library (`GetImageLibraryTargets`, async) + seeds the hand-typed `local-targets.json` sidecar; (2) **`Button_LoadImageLibrary`** / **`Button_LoadJsonTargets`** scan the configured `ImageLibraryRoot` / `NinaTargetsRoot` (falling back to a folder browse with path-persistence when a root yields nothing); (3) **`Button_BrowseTargetList`** is a no-persist browse over picked files or a recursive folder, for *both* `.json` and `.xisf`; (4) **drag-and-drop** of any mix from Explorer onto `CheckedListBox_SelectedTargets` (no persist). Roots resolve via `MainForm.NinaTargetsRootPath` / `ImageLibraryRootPath` from `mAppSettings`; edit via `Defaults > Edit settings.json`. The recursive walk is `Targets/TargetScanner.cs` (error-tolerant — unreadable directories logged and skipped; comet folders, named `Comet …`, excluded). It **groups** files and resolves one `Target` per group at the spherical centroid (`Targets/SkyCentroid.cs`). Per-file parsing is `Nina/TargetLoader.cs` / `ImageLibrary/ImageLibraryLoader.cs`. Orchestration lives in `Forms/Presenters/MainForm.TargetLoadingPresenter.cs`.
- `Forms/MainForm.Designer.cs` is ~1400 lines of generated designer code — edit via the Visual Studio designer, not by hand.
- **Neither Core nor TP carry static mutable state.** Pure-Meeus path since the CS-removal; TP-side `Support/AstrometryUi.cs` migrated to an immutable `record` (with `AstrometryUi.For(location)` factory + `MainForm.mAstrometryUi` field). Any future shared state should follow the same pattern: snapshot record + form-side field, never `static`-mutable.
- **`CheckedListBox` owner-draw is broken.** `CheckedListBox.DrawMode` is hard-coded to `Normal` (setter is a silent no-op) and `OnDrawItem` paints checkbox+text without calling `base.OnDrawItem`, so the standard `DrawItem` event never fires. Custom row painting requires the `Forms/DupeAwareCheckedListBox.cs` subclass which re-enables `LBS_OWNERDRAWFIXED` via `CreateParams` and owns the row paint via overridden `OnDrawItem` (consumes a `Func<int, Color?> RowBackground` callback).
- **Listbox items are `TargetRow` wrappers, not bare strings.** `MainForm.PopulateCheckedListBoxFromTargets` adds `new TargetRow(t)` per row (`ToString() => t.Name`); index-based lookup goes through `MainForm.TargetForRow(index)` which casts and returns the `Target`. The previous `Items[i].ToString()` + `KnownTargets.FirstOrDefault(x => x.Name == name)` pattern collapses two same-name rows to the first match. New listbox callsites must use `TargetForRow` / cast `CheckedItems` entries to `TargetRow`.
- **Notes folder layout.** Observation-debug artifacts live under `%APPDATA%\TargetPlanner\Logs\` — `tp.log` (current session) + `tp.log.prev` (one session back, rotated on startup) + `screenshots/` + `screenshots.prev/`. `Log.StartNewSession()` (called from `Program.Main` after `VelopackApp.Build().Run()`) rotates both directories together so references in `tp.log.prev` to PNG paths under `screenshots.prev/` stay valid. `Log.NotesFolderPath` surfaces the directory programmatically; Help → Feedback → Open Notes Folder is the user-facing entry.
- **`Log.Diag(category, message)` is the semi-permanent diag channel.** Writes to `tp.log` tagged `DIAG/<category>` regardless of build configuration. Categories filtered via `TP_DIAG` environment variable (comma-separated, `"*"` for all, empty/unset for none). Debug builds default to all-on; Release defaults to off. Wrap expensive interpolations: `if (Log.IsDiagEnabled("Day")) Log.Diag("Day", $"...");`. Current categories: `Coord`, `Cache`, `Day`, `Sky`, `UI`, `Overlay` — grep for `Log.Diag(` callers to confirm.
- **Observation dialog (Ctrl+N) is solo-dev infrastructure.** `Forms/UserObservationDialog.cs`, modeless + TopMost. OK writes a self-contained `USER_OBS_END id=<4-hex>` line capturing notes + auto-captured ctx snapshot (`MainForm.GetObservationContext`) + auto-captured MainForm screenshot path (`Graphics.CopyFromScreen` because LC2's SKControl returns blank from `Control.DrawToBitmap`). `USER_OBS_START`/`CANCEL` bracket the user's investigation window; DIAG lines between them by timestamp. Surface via Help → Feedback menu.

## Core consumer contract

These are the explicit guarantees / expectations Core makes of its consumers (TargetPlanner today, XisfManager and a planned NINA scheduler plugin tomorrow). Preserve them when editing Core public API.

- **Collection returns are `IReadOnlyList<T>`.** Every Session / Moon helper that returns a list (`VisibilityWindows.For`, `QualitySamples.OverNight`, `MoonSeparation.IntervalsAboveDeg`, `BestSession`-style planners) types the return as `IReadOnlyList<T>`. Stick to that for any new Core method — callers are allowed to assume immutability, ordering stability, and no-nulls without checking.
- **DateTime.Kind contract.** `NightWindow.AstronomicalDawn` / `AstronomicalDusk` are `DateTimeKind.Utc` — absolute UTC instants. Core methods that take a `DateTime utc` parameter (`AltAz.At`, `NightCalculator.ComputeNight`, `SiderealTime.Local`, `JulianDate.FromUtc`, `MoonSeparation.DegreesAt`) route through `Astronomy.Core.Time.TimeKindGuard.AsUtc` (internal): `Local`/`Unspecified` are converted via the machine zone; `Utc` is a no-op. The recommended TP-side carrier for an observation moment is `Astronomy.Core.Time.ObservationMoment` (record struct, `(Utc, Zone)`) — consumers build it via `FromLocal(local, zone)` or `Now(zone)` and pass `.Utc` to math helpers. The trap to avoid: don't call `.ToUniversalTime()` on a `DateTimeKind.Unspecified` instant that was originally computed under a different UTC offset (legacy CoordinateSharp wall-clock-at-offset returns) — was the source of DST-transition bugs.
- **Signed-degree inputs.** `TargetGeometry.MeridianAltitude`, `HourAngleAtAltitude`, `AltitudeAtHourAngle`, `AzimuthAtHourAngle` take **signed** lat / dec. The caller resolves the hemisphere flag (`latDeg = location.North ? +location.Latitude : -location.Latitude`). `AltAz.At` is the canonical resolution idiom — new helpers should follow that shape rather than re-exposing another `North` bool.
- **No static mutable state** in Core. Pure-Meeus path; every helper threads instances through parameters; consumers are free to call from any thread without external synchronization.

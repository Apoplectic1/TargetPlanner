# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Windows Forms desktop tool for astrophotography planning, plotting target altitude over time with multi-target overlay. Targets load from two on-disk formats — NINA sequence files (`.json`) and `.xisf` images — recursively scanned by `Targets/TargetScanner.cs`, which groups each target's files (capture frames, mosaic panels) and resolves one `Target` at the spherical centroid of the group (`Targets/SkyCentroid.cs`). **User-facing behaviour, defaults, and chart UX live in [README.md](README.md)** — this file focuses on code organisation, conventions, and gotchas for a coding agent. Settings-resolved target roots: `MainForm.NinaTargetsRootPath` / `MainForm.ImageLibraryRootPath`. Single render entry point: `Button_Graph_Click` → `mCoordinator.ApplyImmediateAsync(SnapshotCurrent(targets))` which awaits the cache prepare chain then dispatches into the active sub-chart's `Render(...)` (no startup auto-build). On startup the image library auto-loads (async, `GetImageLibraryTargets`); the post-load handler seeds `mSelection.SelectedSingle` to the first sorted target.

ROADMAP entry: "2026-05-17 — Chart-pipeline SoC pipeline collapse + observation dialog + Library Saemundsson."
- **ChartContext** — immutable record snapshot in `State/ChartContext.cs` capturing all chart-pipeline inputs (`Location`, `Targets`, `Policy`, `Observation`, `ActiveArea`, `TargetColors`, `DayMode`) plus a derived `Hdm` property that keys the fits cache. `Observation` is an `Astronomy.Core.Time.ObservationMoment` carrying the per-session UTC + site zone (post-Phase-2 replacement for the legacy `mLocalDateTime` tuple field). Reference-identity-compared inside `HdmKey` so a reloaded policy invalidates the fits cache automatically.
- **PlanningPreferences** — immutable record in `State/PlanningPreferences.cs` carrying `(TargetFloorDeg, MinDuration)`. Per-site user-pref subset of `PlanningPolicy`; persisted on `NamedSite.Preferences` (the shared Astronomy.NINA DTO) as nested JSON. MainForm holds one `mPlanningPreferences` field; spinner edits use `with` syntax. Spinner handlers also mirror back to the active NamedSite via `PersistPlanningPreferencesToActiveSite()` so the close-time `SettingsStore.Save` persists the latest values rather than the stale Preferences DTO that was set at site-pick time. Replaces the pre-Phase-2 `mLocation.With(horizon:, duration:)` per-tick edits on the now-removed `Location.Horizon` / `.Duration` scalars.
- **ChartEvaluation** — single-field record in `State/ChartEvaluation.cs` returned by `IChartCacheStore.EnsureAsync(ctx, dayKey)`, carrying just `BrightnessInputsChanged`. Consumed only by the coordinator's post-apply hook, which gates `PushSkyKSInputs(ctx)` on it (Sky's Render walks K-S inline when Sky is active, so the hook is load-bearing for the "Sky not active + BrightnessInputs changed" case). **Not** threaded through sub-chart `Render`. The Tier-3 dead-code sweep (2026-05-19) dropped the four diag-only axis flags (`LocationChanged` / `TargetsChanged` / `HdmChanged` / `DayModeChanged`), the three zero-read keys (`DayKey` / `HdmKey` / `DayMode` — sub-charts compute their own dayKey and read `ctx.Hdm` / `ctx.DayMode`), and the dead `ChartEvaluation eval` parameter on `IAltitudeSubChart.Render`. Phase 7's per-sub-chart short-circuit was shipped (`97f5dc2`) then reverted (`759f968`) on LC2 paint instability across hidden→visible `Control` transitions; ChartEvaluation is the residue, now slimmed to its one live field.
- **ChartCoordinator** — thin funnel in `State/ChartCoordinator.cs`. Pipeline is `RunPipelineAsync(ctx)`: generation bump → compute `dayKey` via `NightCalculator.ComputeNight(ctx.Location, ctx.Observation.Utc)` (always fresh, never reads cache state which may be stale pre-`SetLocationAsync`) → `await mCache.EnsureAsync(ctx, dayKey)` → generation guard → `mRenderActiveArea(ctx)` → `mPostApplyHook(ctx, eval)`. Owns supersedence via a monotonically-increasing `mGeneration` counter (each pipeline captures its gen at entry and bails before any side-effecting write if a newer Apply has run in the meantime). 150 ms internal debounce. Every UI handler reduces to `mCoordinator.Apply(SnapshotCurrent(...))`; `LastAppliedTargets` is the canonical source of the active target set for callers that need to re-snapshot (sort changes, picker scrubs). Pre-2026-05-17 the coordinator owned a per-area diff table + 3-way dispatch (`Render` / `RefreshVisibility` / `ShowOnly`); all that logic moved into the cache's `EnsureAsync` (`07f49f0`, 91 ins / 330 del).
- **EnsureAsync** — `IChartCacheStore.EnsureAsync(ctx, dayKey)` is the single pre-render pipeline. Diffs `ctx` against `mLastEnsureCtx` (per-Location value-equivalence via `LocationCacheEquivalent`, Targets ref-list, Hdm key, DayMode, brightness inputs) plus the date axis (`ctx.Observation.Utc` vs `mLastSetUtc` shadow), runs `SetLocationAsync(loc, utc)` (if location-or-date-relevant fields changed) + `PrepareMoonAsync` (target-independent, fires whenever dayKey is valid) + `PrepareManyAsync` / `PrepareFitsAsync` / `PrepareDayAsync` (per-target, only when `ctx.Targets.Count > 0`), and returns a populated `ChartEvaluation`. Replaced the coordinator's per-axis Prepare call chain in the 2026-05-17 pipeline collapse.
- **Observation dialog** (Ctrl+N) — solo-dev debugging infrastructure. `Forms/UserObservationDialog.cs`, modeless + TopMost. Writes `USER_OBS_START id=<4-hex> build=<MinVer-sha>` on open, `USER_OBS_END id=<...> ctx=(...) screenshot=<path> checked=[...] notes="..."` on OK (autocaptures MainForm screenshot + planner state via `MainForm.GetObservationContext`), `USER_OBS_CANCEL id=<...>` on Cancel/X. Singleton — re-pressing Ctrl+N focuses the existing dialog. Surface via Help → Feedback menu (tooltip). Logs/screenshots under `%APPDATA%\TargetPlanner\Logs\` (one delete clears the whole footprint).

**Domain terms in the chart code** (user-facing definitions live in [README.md](README.md#domain-terms); the mapping below is for locating implementation):
- **HD Overlay** — Day-chart click-toggled best-window step function. Computed via `BestSession.For`; the LC2 `OverlayController` (sibling to `AltitudeSubChart_Day`) owns the state machine, swapping each `LineSeries<ObservablePoint>`'s data array between the original altitude curve and the `floor`-inside-window / `0`-outside-window step shape. Right-click is `ToggleAll` (apply-all when no backups, restore-all when any are active; apply-all enters "global mode" where `EnsureGlobalApplied` auto-extends overlay to newly-fitting targets across H/D/M scrubs and target-add reconciliation). Per-target left-click works in both modes — in global mode it carves an opt-out tracked in `mGlobalOptOuts` so the toggled-off target stays bare across scrubs (bidirectional: toggle-on removes the opt-out). Sticky fast-path: a left-click at the IDENTICAL pixel as the last successful toggle re-toggles that target without a hit-test, so rapid flip works without moving the cursor to re-intersect the redrawn curve.
- **D-hour window** — `Astronomy.Core.Session.BestSession.For`. `PlanningPreferences.MinDuration` is the floor (post-Phase-2; previously `Location.Duration`).
- **Ceiling / Floor / Symmetric** — three `LineSeries<ObservablePoint>` per target on `AltitudeSubChart_Sessions`. ONE legend item per target — clicking it toggles all three series' `IsVisible` together. `BestSession.ResolveCandidates` resolves visibility ∩ moon-clear once per night so `PlaceBest` (Ceiling/Floor) and `PlaceCentered` (Symmetric) see identical inputs.

## Architecture

The codebase is split at the repo boundary: **`Astronomy.Core`** lives in the sibling `Library\` repo and provides pure, UI-free astronomical math plus POCOs; **`TargetPlanner`** (this repo) is the WinForms chart/host/UI on top, consuming Core via `ProjectReference`. Two newer sibling libraries (`Astronomy.XISF` for header-only XISF reads, `Astronomy.NINA` for the rich `Target` shape + image-library scanner) shipped 2026-05-18 and are sln-visible but not yet ProjectReferenced from TP — Phase C of the multi-library plan migrates TP onto `Astronomy.NINA.Target`. The TP-side architecture has been through a three-phase SoC refactor (commits `0f6c81c` / `1e1986d` / `3425f8e`) plus a follow-on orchestration-layer refactor: chart construction is decoupled from cache construction, cache state is decoupled from selection state, selection state is decoupled from UI controls, and an explicit **`ChartCoordinator`** funnels every UI handler's downstream effects through one diff-and-dispatch pipeline. Concretely:

- **Selection state** lives in `TargetPlanner/State/TargetSelection.cs` — observable VM owning `KnownTargets`, `SelectedSingle`, `Checked`. UI controls (combo, listbox, buttons, RA/Dec inputs) are views: user input flows into the VM via mutators (`SetKnownTargets`, `SetSelectedSingle`, `SetChecked`, `SetCheckedSet`, `SetAllChecked`, `AddKnownTarget`, `RemoveKnownTarget`); VM events (`KnownTargetsChanged`, `SelectedSingleChanged`, `CheckedSetChanged`) flow back to UI under a `mUpdatingUiFromVm` echo guard. **Button_Graph and the checked-set are independent views**: clicking Button_Graph after checking targets renders just the combo target while the checkboxes stay ticked — the next checkbox toggle re-renders the full checked set, producing a visible jump from single to multi. That's the rule; switching paradigms is the user's explicit action. Highlighting a row in `CheckedListBox_SelectedTargets` (text, not checkbox) updates combo + RA/Dec via `SetSelectedSingle` only; `CheckedSetChanged` doesn't fire, so the chart is unchanged. **Add / Remove buttons** explicitly mutate `KnownTargets` (Add merges the resolved `SelectedSingle` into `Checked`, persisting locally-typed targets to `%AppData%\TargetPlanner\local-targets.json` via `Settings/LocalTargetStore.cs`; Remove drops from `KnownTargets` entirely, sidecar too if locally-added). The sidecar is merged into `KnownTargets` after every NINA `Load(...)` so a re-browse doesn't wipe locally-added targets.
- **Cache state** lives in `TargetPlanner/Caches/ChartCacheStore.cs` — single-writer cache with four axes: `(Location, Target)` for yearDays, `(Target, HdmKey)` for fits (the `TargetFitEntry` carries both a per-night `Nights[i]` array AND a single-night `Tonight` slot — `Nights` keys Year + Sessions, `Tonight` keys Day's HD overlay + Sky's hide-on-no-fit, single source of truth across all four charts), `(Target, DayWindowKey)` for Day per-minute target altitudes, and `DayWindowKey → MoonAltitudeEntry` for per-minute moon altitudes (singleton, target-independent — added 2026-05-17). The **public surface is `EnsureAsync(ctx, dayKey) → ChartEvaluation`** — single pre-render entry that runs the right Prepare paths based on its own diff against `mLastEnsureCtx` plus a date diff against `mLastSetUtc` (`ctx.Observation.Utc.Date` / `NightCache.ComputeYearStartDay`). Sub-charts read via the sync `GetOrNull` (yearDays) / `GetFitOrNull` (fits) / `GetDayOrNull` (Day altitudes) / `GetMoonOrNull` (moon altitudes); `EnsureAsync` runs the matching `PrepareManyAsync` / `PrepareFitsAsync` / `PrepareDayAsync` / `PrepareMoonAsync` build paths (the per-axis `Get*OrBuildAsync` builders are internal to `CacheAxis`). `LocationCacheEquivalent` (post-Phase-2: pure geometry — Lat/Lon/North/West/Elevation) lives on the cache and gates `SetLocationAsync(loc, utc)`; the date axis is the separate `mLastSetUtc` diff in `EnsureAsync`. The store owns the heaviest Meeus paths in the chart pipeline.
- **Rendering** lives in `TargetPlanner/Charts/`. All four chart areas (Day / Sky / Year / Sessions) are LiveCharts2 v2.1.0-dev-365 sub-charts implementing `IAltitudeSubChart`. MS Charts (`System.Windows.Forms.DataVisualization`) is gone. MainForm holds `Dictionary<string, IAltitudeSubChart> mSubCharts` keyed by area; `MainForm.ShowOnlyAltitudeChart` flips `Visible` per radio. Each sub-chart's `Render(ChartContext, IChartCacheStore)` takes a single immutable snapshot. **Sub-charts are render-only**: Day reads per-minute target altitudes from `cache.GetDayOrNull(target, dayKey)`, per-minute moon altitudes from `cache.GetMoonOrNull(dayKey)`, and tonight's window from `cache.GetFitOrNull(target, ctx.Hdm)?.Tonight`; Sky walks K-S brightness inline but reads its moon overlay altitudes from the same `GetMoonOrNull(dayKey)` and its fit gate from `Tonight.Floor.HasValue`; Year and Sessions read `Nights[i]` for per-night Floor / Ceiling / CenteredFloor. Zero UI-thread `BestSession.For` / `AltAz.At` / `AstroUtil.GetMoonAltitude` calls in any cache-warm Render path (defensive inline fallbacks exist in moon paths for cache-miss races but log a WARN if they fire). No `Task.Run` / `BeginInvoke` / `CancellationTokenSource` in sub-charts. **Sub-charts always Render** — Phase 7's per-sub-chart short-circuit was shipped and reverted (LC2 paint instability across hidden→visible `Control` transitions). Detailed lessons-learned archive at `~/.claude/plans/i-thought-i-d-take-valiant-neumann.md` and `~/.claude/plans/in-a-recent-commit-snug-flame.md`.
- **Orchestration**: `TargetPlanner/State/ChartContext.cs` is an immutable record snapshot of the inputs to the chart pipeline (`Location`, `Targets`, `Policy`, `Observation`, `ActiveArea`, `TargetColors`, `DayMode`) plus a derived `Hdm` property (`HdmKey { HorizonDeg, DurationTicks, Profile, FilterCenterNm, LocalHorizon }`) that keys the fits cache. `Observation` is the per-session `(Utc, Zone)` carrier (Library type `ObservationMoment`) — sub-charts read `ctx.Observation.Utc` for now-line / dawn-dusk anchoring. `TargetPlanner/State/ChartCoordinator.cs` is now a thin funnel: pipeline is `NightCalculator.ComputeNight(ctx.Location, ctx.Observation.Utc)` → `await mCache.EnsureAsync(ctx, dayKey)` → generation guard → `mRenderActiveArea(ctx)` → `mPostApplyHook(ctx, eval)`. The cache's `EnsureAsync` is the single seam where staleness reasoning + downstream Prepare calls happen — pre-2026-05-17 the coordinator owned this dispatch via a per-area diff table + 3-way `Render` / `RefreshVisibility` / `ShowOnly` branching, all of which collapsed in `07f49f0` (91 ins / 330 del). UI handlers reduce to `mCoordinator.Apply(SnapshotCurrent(...))` (debounced 150 ms) or `mCoordinator.ApplyImmediateAsync(...)` (no-debounce, awaitable, for combo location pick + `RunGraphBuildAsync` + `ResetForLocationChange`). The coordinator owns supersedence via a monotonically increasing `mGeneration` counter — each pipeline captures its gen at entry and bails before any side-effecting write if a newer Apply has run in the meantime. The cache de-dupes per-(target, key) builds so overlapping pipelines don't double-compute. **The cache is the single seam where downstream effects of any UI change are decided.** `MainForm.RenderArea` calls `sc.Render(ctx, mCache)` followed by `ShowOnlyAltitudeChart(sc.Control)` then `sc.Control.Refresh()` — the synchronous Refresh after the `Visible=true` flip is load-bearing for the moon overlay's first paint after a hidden→visible cycle (LC2's SKControl drops Fill-only `LineSeries` from its paint output without the kick).

Threading model is now explicit:
- **UI thread**: form events, VM mutations, coordinator pipeline, render passes, chart paint. The coordinator's `Apply` / `ApplyImmediateAsync` / debounce tick / generation-guarded pipeline all run on the UI thread; the only off-thread work is the awaited cache compute below.
- **Cache worker** (`Task.Run` inside `ChartCacheStore`'s `BuildEntryAsync` / `BuildFitEntryAsync` / `BuildDayEntryAsync` / `BuildMoonEntryAsync`): per-target year-cache builds, per-Location `NightCache` build, per-(target, HdmKey) fit builds (one pass produces both the year `Nights[i]` array and the `Tonight` slot), per-(target, DayWindowKey) Day altitude builds. Library is lock-free / managed-only since the `2249834` CS-removal; per-key in-flight de-dupe inside the cache prevents redundant compute, and parallel-across-cores follows from the threadpool naturally. No in-flight cancellation infrastructure — stale work (e.g. a build started against a since-swapped Location) runs to completion and discards itself at publish via each cache axis's `ReferenceEquals(mLocation, buildLocation)` check. The cache surface takes no `CancellationToken` parameters. Form-lifecycle cancellation is the one CTS (`mFormClosingCts` on MainForm), observed only at the outer `Task.WhenAny(warmupTask, cancelledTask)` boundary in the NINA-load warmup (`MainForm.cs:1869`) — the cache itself doesn't observe the token. **Perf budget**: post-`2249834` cache pre-population is **2–4 sec for 44 targets** (yearDays) plus a few seconds for fits on the dev machine (was ~17 min pre-CS-removal). Design future cache work against this ceiling.
- **NINA loader** (`Task.Run` inside `MainForm.GetNinaTargets`): file enumeration + JSON parse. Result published into the VM via `mSelection.SetKnownTargets`, which fires `KnownTargetsChanged` on the UI thread. The form's tail then kicks off background `mCache.PrepareManyAsync(allLoaded)` followed by `mCache.PrepareFitsAsync(allLoaded, currentHdm)` so the user's first Sessions / Year click hits a warm cache and renders instantly.

## Conventions worth knowing before editing

- **RA is decimal hours** (`[0, 24)`) in `Target.RightAscension`. The UI presents D/M/S of arc only for Declination; RA D/M/S are derived hour/minute/second fields. Core's `AltAz` and `TargetGeometry` consume `RightAscension` directly as hours.
- **Signed hemispheres** are an TargetPlanner / Core convention: `Latitude`, `Longitude`, `Declination` are stored as positive magnitudes with a paired `North` / `West` flag. Core helpers that take "signed degrees" (e.g. `TargetGeometry.MeridianAltitude`) expect the caller to resolve the flag — see `AltAz.At` for the canonical resolution idiom.
- **Type-alias usings for Core types.** Files in `TargetPlanner.*` namespaces that reference `Astronomy.Core.Targets.Target` use a `using Target = Astronomy.Core.Targets.Target;` alias at the top. This is defensive: if a sibling `TargetPlanner.Target` namespace ever reappears, C# enclosing-namespace lookup would shadow the type otherwise. No such namespace exists today.
- **Defaults resolve at runtime, two layers deep** (post-2026-05-19 collapse). `settings.json` (`%AppData%\TargetPlanner\settings.json`, the single user-state file) → hardcoded C# seed in `PersonalDefaults.BuildSeedSettings()` (factory returning a fresh `AppSettings` with `LastSelectedLocationName`, `NinaTargetsRoot`, and 4 NamedSites). `SettingsStore.Load` paths: missing file → call the factory, save, return; present file → deserialise, apply **Pattern C** (fill any null/empty top-level field from the seed -- additive-schema migration self-heal), strip any saved "Custom"-named site (sentinel-reservation for `ComboBox_Location`'s free-edit row). No more `MergeBuiltins` zero-fill (which was the cause of the personal-defaults-vs-settings sync confusion that prompted the collapse). The previously-paired gitignored `%LocalAppData%\TargetPlanner\personal-defaults.json` is no longer read; existing files on disk are unused dead weight. `File > Defaults > Edit settings.json` launches the OS-default editor; `File > Defaults > Clear (factory reset)` wipes settings.json + filters.json + local-targets.json + Logs/ and exits TP. Both paths set `mSuppressFormClosingSave` before `Application.Exit()` so the exit-time save doesn't clobber the user's just-completed hand-edits or just-deleted state. Boot picks `mAppSettings.LastSelectedLocationName` (was `PersonalDefaults.LocationName` pre-collapse; behaviour change: TP now boots to whatever site was last selected rather than always to the personal-default).
- **`Location.Elevation`** (meters above geoid, default 0) is honored by `MoonSeparation.ObserveAt` (parallax via `MoonPosition.Topocentric`, ~0.5″ per 1000 m) and by `AstroUtil.GetSunRiseAndSet` / `GetMoonRiseAndSet` (refracted horizon dip via `MeeusUtility.HorizonDipDeg`, ~0.26° at 80 m / ~2.93° at 10000 m, shifting moon-rise/set by ~25 sec / ~11 min respectively). Civil/Nautical/Astronomical twilight thresholds (-6/-12/-18) are by convention NOT elevation-corrected -- they reference the celestial horizontal plane.
- **Target sources & roots.** Four entry points load targets, each **adding** to the known-target set (duplicates skipped via `TargetIdentity` — never a wholesale replace; `Button_ClearAllTargets` is the only path that empties it): (1) **startup** auto-loads the image library (`GetImageLibraryTargets`, async) and seeds the hand-typed `local-targets.json` sidecar into `KnownTargets`; (2) **`Button_LoadImageLibrary`** / **`Button_LoadJsonTargets`** scan the configured `ImageLibraryRoot` / `NinaTargetsRoot` (`.xisf` / `.json` respectively), falling back to a folder browse — whose chosen path is persisted to settings — when a root yields nothing; (3) **`Button_BrowseTargetList`** is a one-off, no-persist browse that scans the picked files, or a folder recursively, for *both* `.json` and `.xisf`; (4) **drag-and-drop** of any mix of `.json`/`.xisf` files and folders from Explorer onto `CheckedListBox_SelectedTargets` (one-off, no persist) — behaves identically to Browse. Roots resolve via `MainForm.NinaTargetsRootPath` / `ImageLibraryRootPath` from `mAppSettings`; edit via `Defaults > Edit settings.json` (or the `PersonalDefaults.BuildSeedSettings()` seed) — never inline a path at the consumer. The recursive walk is `Targets/TargetScanner.cs` (error-tolerant — an unreadable directory is logged and skipped; no directory skipped by name; comet folders, named `Comet …`, excluded). It **groups** a target's files and resolves one `Target` per target at the spherical centroid of the group (`Targets/SkyCentroid.cs`): `.xisf` by target folder (above `Captures/`) over every `IMAGETYP=Light` frame, a mosaic folder being one target; a `.json` mosaic by its `… Panel <n>` folder; a standalone `.json` is one target. Per-file parsing is `Nina/TargetLoader.cs` / `ImageLibrary/ImageLibraryLoader.cs`. `Targets/TargetIdentity.cs` (stars-stripped name + RA/Dec within ~1′) is no longer the collapse mechanism — it serves only the already-loaded / cross-source skip and the listbox duplicate tint. The orchestration (`GetImageLibraryTargets` / `GetJsonTargets` / `GetBrowsedTargets` / `GetDroppedTargets` → `ScanPathAsync` → `AddScannedTargets` → cache-warmup) lives in `Forms/Presenters/MainForm.TargetLoadingPresenter.cs`.
- `Forms/MainForm.Designer.cs` is ~1400 lines of generated designer code — edit via the Visual Studio designer, not by hand.
- **Neither Core nor TP carry static mutable state.** Core has been clean since `2249834`; TP-side `Support/AstrometryUi.cs` was the last holdout and migrated to an immutable `record` (with `AstrometryUi.For(location)` factory + `MainForm.mAstrometryUi` field) in the PR-6 follow-on to the architectural-review campaign. Any future shared state should follow the same pattern: snapshot record + form-side field, never `static`-mutable.
- **`CheckedListBox` owner-draw is broken.** `CheckedListBox.DrawMode` is hard-coded to `Normal` (the property setter is a silent no-op) and `OnDrawItem` paints checkbox+text without calling `base.OnDrawItem`, so the standard `DrawItem` event never fires. Custom row painting requires the `Forms/DupeAwareCheckedListBox.cs` subclass which re-enables `LBS_OWNERDRAWFIXED` via `CreateParams` and owns the row paint via an overridden `OnDrawItem` (consumes a `Func<int, Color?> RowBackground` callback). Don't try to bring back a regular `CheckedListBox` for any flagged-row use case.
- **Listbox items are `TargetRow` wrappers, not bare strings.** `MainForm.PopulateCheckedListBoxFromTargets` adds `new TargetRow(t)` per row (`ToString() => t.Name`); index-based lookup goes through `MainForm.TargetForRow(index)` which casts and returns the `Target`. The previous `Items[i].ToString()` + `KnownTargets.FirstOrDefault(x => x.Name == name)` pattern collapses two same-name rows to the first match — visible as both rows pushing the same RA/Dec into the spinners on highlight. New listbox callsites must use `TargetForRow` / cast `CheckedItems` entries to `TargetRow`.
- **Notes folder layout** (since 2026-05-17): all observation-debug artifacts live under `%APPDATA%\TargetPlanner\Logs\` — `tp.log` (current session, ERROR / WARN / DIAG / USER_OBS_* lines), `tp.log.prev` (one session back, rotated on startup), `screenshots/` (current session's observation PNGs), `screenshots.prev/` (one back). - **`Log.Diag(category, message)` is the semi-permanent diag channel.** Writes to `tp.log` tagged `DIAG/<category>` regardless of build configuration. Categories filtered via the `TP_DIAG` environment variable: comma-separated list (e.g. `TP_DIAG=Coord,Cache`), `"*"` for all, empty/unset for none. Debug builds default to all-on; Release defaults to off (zero overhead — the `IsDiagEnabled` guard short-circuits before any string interpolation). Wrap expensive interpolations: `if (Log.IsDiagEnabled("Day")) Log.Diag("Day", $"...");`.
- **`tp.log` rotates on every app start.** `Log.StartNewSession()` (called from `Program.Main` after `VelopackApp.Build().Run()`, before MainForm boot) moves `tp.log` → `tp.log.prev` (overwriting any older `.prev`) and rotates the `screenshots/` directory the same way. Each run's diag trail is self-contained; one session back is preserved for postmortem. References from `tp.log.prev` to PNG paths under `screenshots.prev/` stay valid because both rotate together.
- **Observation dialog (Ctrl+N) is solo-dev infrastructure.** `Forms/UserObservationDialog.cs`, modeless + TopMost so the user can interact with the main UI while it stays open. Notes-only since 2026-05-19 (the 12-item CheckedListBox was dropped — items weren't consumed programmatically anywhere; only the free-form notes carried any debug signal). OK writes a self-contained `USER_OBS_END` line: free-form notes (empty/whitespace encodes as `notes="(checkpoint)"` so `grep checkpoint tp.log` finds "all okay" moments), auto-captured ctx snapshot (`area / date / n / H / D / filter / Bortle / K` via `MainForm.GetObservationContext`), auto-captured MainForm screenshot path. `USER_OBS_START` fires on open; `USER_OBS_CANCEL` fires on Cancel/X. Dialog hides itself before screenshot capture so it doesn't appear in the saved PNG. ## Core consumer contract

These are the explicit guarantees / expectations Core makes of its consumers (TargetPlanner today, XisfManager and a planned NINA scheduler plugin tomorrow). Preserve them when editing Core public API.

- **Collection returns are `IReadOnlyList<T>`.** Every Session / Moon helper that returns a list (`VisibilityWindows.For`, `QualitySamples.OverNight`, `MoonSeparation.IntervalsAboveDeg`, `BestSession`-style planners) types the return as `IReadOnlyList<T>`. Stick to that for any new Core method — callers are allowed to assume immutability, ordering stability, and no-nulls without checking.
- **DateTime.Kind contract.** `NightWindow.AstronomicalDawn` / `AstronomicalDusk` are `DateTimeKind.Utc` — absolute UTC instants. Core methods that take a `DateTime utc` parameter (`AltAz.At`, `NightCalculator.ComputeNight`, `SiderealTime.Local`, `JulianDate.FromUtc`, `MoonSeparation.DegreesAt`) route through `Astronomy.Core.Time.TimeKindGuard.AsUtc` (internal): `Local`/`Unspecified` are converted via the machine zone; `Utc` is a no-op. The recommended TP-side carrier for an observation moment is `Astronomy.Core.Time.ObservationMoment` (record struct, `(Utc, Zone)`) -- consumers build it via `FromLocal(local, zone)` or `Now(zone)` and pass `.Utc` to math helpers. The one trap to avoid: don't call `.ToUniversalTime()` on a `DateTimeKind.Unspecified` instant that was originally computed under a different UTC offset (e.g. legacy CoordinateSharp wall-clock-at-offset returns) — that was the source of the 2026-11-01 / 2027-03-14 DST-transition bugs fixed in commit `5eb3d0b`.
- **Signed-degree inputs.** `TargetGeometry.MeridianAltitude`, `HourAngleAtAltitude`, `AltitudeAtHourAngle`, `AzimuthAtHourAngle` take **signed** lat / dec. The caller resolves the hemisphere flag (`latDeg = location.North ? +location.Latitude : -location.Latitude`). `AltAz.At` is the canonical resolution idiom — new helpers should follow that shape rather than re-exposing another `North` bool.
- **No static mutable state** in Core. Pure-Meeus path since `2249834` — every helper threads instances through parameters; consumers are free to call from any thread without external synchronization.

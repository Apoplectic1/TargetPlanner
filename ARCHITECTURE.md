# TargetPlanner architecture

Deep architecture reference for `TargetPlanner`. Read this when editing `Charts/`, `Caches/`, `State/`, `Filters/`, or any of the chart-pipeline paths in `Forms/MainForm.cs`. For the high-level overview (repo split, SoC phases, threading model), the **Glossary**, the **Conventions worth knowing before editing**, and the **Core consumer contract**, see [CLAUDE.md](CLAUDE.md). User-facing behaviour, defaults, and chart UX live in [README.md](README.md).

The codebase is split at the repo boundary: **`Astronomy.Core`** lives in the sibling `Library\` repo and provides pure, UI-free astronomical math plus POCOs; **`TargetPlanner`** (this repo) is the WinForms chart/host/UI on top, consuming Core via `ProjectReference`. The TP-side architecture has been through a three-phase SoC refactor (commits `0f6c81c` / `1e1986d` / `3425f8e`), a cache-completion pass (lifts per-(target, H/D/M) fit compute out of the sub-charts and into `ChartCacheStore` — design rationale at [`docs/design/chart-fits-cache.md`](docs/design/chart-fits-cache.md)), then a multi-PR architectural-review campaign (commits `c74224f` → `17db0b0`, 2026-05-13) that introduced `PlanningPolicy`, lifted Day altitude compute into a third cache axis, replaced CTS-based supersession with a generation counter, converted `AstrometryUi` to an immutable record, dropped `mLastRenderedTargets` + `IAltitudeSubChart.Reorder` in favour of coordinator-owned target SoT, and split MainForm presenter clusters into partial-class files. A post-campaign re-review pass (2026-05-13) followed: `[Obsolete]` on `Location.Horizon` / `Location.Duration` to lock in `PlanningPolicy` as the planning-scalar owner; `UpdateHorizonLine` now takes `Policy.TargetFloorDeg` (the user's scalar spinner) rather than `LocalHorizon.MinAltitude` so the green chart line tracks the spinner instead of dipping with the polyline; and Day's `ComputeBestDayWindow` + Sky's `HasFit` are gone — both now read tonight's fit off the new `TargetFitEntry.Tonight` slot, so the entire chart pipeline makes zero UI-thread `BestSession.For` calls. **The 2026-05-17 chart-pipeline collapse refactor** (commits `cafbf3c` → `aa3e082`) then went further: a typed `ChartEvaluation` record output from a new single cache entry-point `EnsureAsync(ctx, nightDate)` replaces the coordinator's per-axis Prepare call chain + its per-area diff table + its 3-way `Render` / `RefreshVisibility` / `ShowOnly` dispatch; the coordinator collapses to a thin generation-bumped `EnsureAsync → Render → PostApply` pipeline (`07f49f0`, 91 ins / 330 del). A fourth cache axis (target-independent moon ephemeris) was added so both Day and Sky read moon state from cache rather than computing inline (`923a5b6`). `AstrometryUi.cs` is deleted; `RefreshAstrometryLabels` reads `NightWindow` directly from `cache.LocationNightCache.Starting` with `NightCalculator.ComputeNight` fallback (`796d92d`). **The 2026-05-28 NightDate axis rekey** (TP `c3ca26b` + AL `4a0f309`) extracted the per-minute compute into AL primitives (`AltitudeCurve.Sample` returning `IReadOnlyList<AltAzSample>`, new `MoonEphemeris.Sample` returning `IReadOnlyList<MoonSample>` with topocentric parallax + apparent altitude), and switched the two per-night cache keys from `DayWindowKey` to `NightDate` (`readonly record struct NightDate(DateOnly DuskDate)`, evaluated under the site's `TimeZoneInfo`). Aligns TP's cache shape with the planned IS Plugin (ISP) cache; AL surface stabilized before ISP design starts. Chart construction is decoupled from cache construction, cache state is decoupled from selection state, selection state is decoupled from UI controls, and **sub-charts are now render-only synchronous painters** that read pre-built data from the cache on every axis. Threading model: UI thread owns form events / VM mutations / render passes / chart paint; cache worker (`Task.Run` inside `ChartCacheStore`'s `BuildEntryAsync` / `BuildFitEntryAsync` / `BuildTrajectoryAsync` / `BuildMoonEphemerisAsync` build delegates) owns per-target year-cache builds, per-Location `NightCache` build, per-(target, HdmKey) fit builds, per-(target, NightDate) trajectory builds, and per-NightDate moon ephemeris builds; NINA loader (`Task.Run` inside `MainForm.GetJsonTargets`) owns file enumeration + JSON parse plus the post-load `PrepareManyAsync` + `PrepareFitsAsync` warmup chain.

## `Astronomy.Core` — pure math, no UI (source in `..\Library\Astronomy.Core\`)

Shared library targeting `net10.0-windows` (via `Directory.Build.props`) with `<Nullable>enable</Nullable>` and `LangVersion latest` (C# 14 today), authored in the sibling `Library\` repo at `E:\Projects\VisualStudio\Astronomy\Library\Astronomy.Core\`. Consumed today by TargetPlanner via `ProjectReference`; designed to be consumed by XisfManager / IS / ISP / ISS without re-porting. The whole portfolio (TP, Astronomy.PCL, Astronomy.Core.Tests, NINA upstream, planned ISP) is uniformly net10 as of 2026-05-04 — netstandard2.0 was retired once NINA migrated and the cross-runtime bridge was no longer load-bearing. The surface summary below is a convenience for readers working on TargetPlanner chart code -- the Library repo is the source of truth for API specifics. Surface by subfolder:

- **`Targets/Target.cs`** — **immutable** POCO. Every property is read-only; mutations produce a new instance via `With(...)`. `RightAscension` is **decimal hours** `[0, 24)`; `RaHours` / `RaMinutes` / `RaSeconds` are get-only DMS-component accessors computed on read (not a duplicate store). `Declination` is stored as a non-negative magnitude; the constructor normalizes a negative value by flipping `North` and storing `abs(value)`. `Target.Default` returns M31 defaults. Does **not** carry any chart / WinForms state.
- **`Locations/Location.cs`** — **immutable** POCO. `With(...)` returns a new instance. Latitude / longitude stored as non-negative magnitudes with direction in `North` / `West` flags; a negative magnitude passed to the ctor flips the corresponding flag. D/M/S accessors (`LatDegrees` etc.) are computed on read. Carries `Name`, `Latitude` / `North`, `Longitude` / `West`, `TimeZoneInfo`, `Elevation`, `BortleClass`, `ExtinctionK`, `LocalHorizon` — `Horizon` / `Duration` / `DateTime` were stripped in Location refactor Phase 2 (per-session moment and planning scalars now live on the consumer side, e.g. TP's `ObservationMoment` + `PlanningPolicy`). `Location.Default` returns neutral, ship-safe placeholder values (40°N/75°W); consumer apps resolve their actual site via their own configuration layers (e.g. TargetPlanner's `PersonalDefaults` + `SettingsStore`).
- **`Night/NightWindow.cs`** — struct: `AstronomicalDawn`, `AstronomicalDusk` (both `DateTimeKind.Utc`), `LunarIlluminationFraction`, plus `IsValid` (short-circuits the `DateTime.MinValue` polar-day / polar-night sentinel). See the `Core consumer contract` section in CLAUDE.md for the Kind=Utc rationale and the DST trap it closes.
- **`Time/JulianDate.cs`, `Time/SiderealTime.cs`** — JD from UTC; GMST from JD; LST from UTC + east-longitude.
- **`AltAz.cs`** — `AltAzCalculator.At(target, location, utc)` (explicit `DateTime utc` parameter; `Location` carries no moment of its own since Phase 2). Returns an `AltAz` readonly struct with `Altitude` and `Azimuth` properties (both degrees; azimuth from North, clockwise). Replaces the old `GetAltitudeAzimuth` / `Tuple<double,double>` pattern.
- **`TargetGeometry.cs`** — `MeridianAltitude`, `LowerCulminationAltitude`, `HourAngleAtAltitude` (returns `NaN` for never-reaches, `+Infinity` for always-above), `AltitudeAtHourAngle`, `AzimuthAtHourAngle`. All take signed-degrees lat/dec.
- **`Night/NightCalculator.cs`, `Night/TwilightCalculator.cs`** — `ComputeNight(Location location, DateTime utc)` (−18° astronomical default) and `TwilightCalculator.ComputeNight(location, sunAltBelowDeg)` for the three standard thresholds (−18 / −12 / −6). Both compute dawn/dusk via `SunEphemeris.RiseSet` (in-house Meeus solver) — UTC instants (`DateTimeKind.Utc`), no DST-transition trap.
- **`Horizons/IHorizonProfile.cs`** + `ScalarHorizonProfile`, `PolylineHorizonProfile`, `ObstructionTableHorizonProfile` — abstraction over a horizon altitude function `AltitudeAt(azimuth)`. Scalar wraps the legacy single-double case.
- **`Session/`** primitives (built for the planned interval scheduler; not yet consumed by the TargetPlanner chart):
  - `TransitTime.UtcAtOrAfter` — analytic LST=RA inverse.
  - `IntegratedQuality.OverSession` (Simpson, 20 points) + `IntegratedQuality.SinAltitudeOverSession` (closed form).
  - `VisibilityWindows.For` — above-horizon ∩ night.
  - `BestSession.For` — transit-centered-or-wall-pushed placement across visibility windows. Optional `MoonAvoidanceProfile profile = null` parameter; when non-null and enabled, the candidate windows are intersected with moon-clear sub-intervals via a 1-min Lorentzian sweep before placement (the 10-min sampling belongs to `MoonSeparation.IntervalsAboveDeg`, a separate helper). `null` / `Disabled` falls through to the legacy moon-blind code path byte-for-byte (the backwards-compat hinge for the Day-chart slice).
  - `QualitySamples.OverNight` — slot-size grid.
  - `RiseSet.NextAtOrAfter` — scalar analytic and `IHorizonProfile`-aware (scalar seed + bisection refine).
- **`Moon/MoonSeparation.cs`** — `DegreesAt` (topocentric target-moon angle), `IntervalsAboveDeg` (night intervals above a fixed threshold), and `ObserveAt` (returns `(SeparationDeg, MoonAltDeg, MoonAzDeg)` in one Meeus pass — uses the new `AstroUtil.GetMoonAltAz` to avoid the `MoonPosition.Topocentric`-twice penalty the chart-cache prepare loop used to pay; `DegreesAt` is now a thin wrapper around `ObserveAt`).
- **`Moon/MoonAvoidance.cs`** — `MoonAvoidanceProfile` POCO (immutable, `With(...)` mutators following the `Target` / `Location` pattern; `Disabled` / `Narrowband` 60°/7d / `Broadband` 120°/14d / `Custom(...)` factories) plus pure decision primitives: `LorentzianRequiredSep` (matches the NINA Target Scheduler reference at `AstrometryUtils.cs:126` to 1e-12), `IsRejected` (full decision incl. TS-style relaxation-zone -- MoonDown override intentionally omitted), `RequiredSepWithRelax` (introspection helper).
- **`Moon/LunarAge.cs`** — `DaysAt(utc)` returns days since the most recent new moon via JD math (reference epoch 2000-01-06 18:14 UT, JD 2451550.2597222). Closed-form synodic-cycle estimate; sub-second accurate at the reference, well within Lorentzian tolerance.

## `TargetPlanner` — WinForms host

### UI labels (`MainForm.RefreshAstrometryLabels`)

The 2026-05-17 pipeline-collapse refactor (`796d92d`) deleted `Support/AstrometryUi.cs`. The record had been doing its own `NightCalculator.ComputeNight(location)` on every form-spinner tick — structurally identical to `ChartCacheStore.LocationNightCache.Starting` — and that duplicate compute path was the root cause of form/chart illumination divergence noted in earlier debugging sessions.

`RefreshAstrometryLabels()` now reads `NightWindow` directly from the cache (`mCache?.LocationNightCache?.Starting`) with a `NightCalculator.ComputeNight(mLocation)` fallback for early-init paths that fire before `mCache` is constructed. The three NightWindow-derived labels (Astronomical Dusk, Astronomical Dawn, Lunar Illumination Fraction) come from there. The five remaining labels (Sun Altitude, Lunar Altitude, Lunar Phase, Moon Rise, Moon Set) are computed inline via `SunPosition.AltAzAt` + `AstroUtil.GetMoonAltitude` + `AstroUtil.GetMoonPhaseName` + `AstroUtil.GetMoonRiseAndSet` — ~150 µs of Meeus per call, cheap enough to fire on every spinner tick without debouncing.

The function is called from `UpdateLocalDateTimeEvents` (DatePicker/Button_Now), `OnLocationEdited` (lat/lon/elevation spinners), `ComboBox_Location_SelectionIndexChanged` (preset picks), and the coordinator's post-apply hook. The cache is the single source of truth for `NightWindow` data across both the form labels and the chart rendering — no more parallel-compute path.

### Target ingestion (`Targets/TargetScanner.cs`, namespace `TargetPlanner.Targets`)

`TargetScanner.ScanAsync(path, kinds, ct)` recursively walks a file or directory tree, error-tolerant — an unreadable directory is logged and skipped, never fatal — and skips no directory by name (comet folders, named `Comet …`, are excluded as targets). It resolves **one `Target` per real sky target**: a target is a *group* of files, collapsed to one `Target` whose coordinate is the spherical centroid of the group (`Targets/SkyCentroid.cs` — RA/Dec → unit vector → vector mean → back, seam-safe at 0h/24h and the poles). `.xisf` is grouped by target folder (the folder above `Captures/`), centroid over every `IMAGETYP=Light` frame parsed by `ImageLibrary/ImageLibraryLoader.cs` — a mosaic folder is one target across all panels; the per-frame `RA`/`DEC` keyword is the dithered plate-solve (scatters 12–14′), so the centroid, not any single frame, is the stable coordinate. A `.json` mosaic is a folder of `… Panel <n>` files (`Nina/TargetLoader.cs` parses each NINA `DeepSkyObjectContainer`), centroid over the panels' planned coordinates; a standalone `.json` is one target. `.xisf` headers parse in parallel off-thread; both parsers are never-throw (a malformed file logs + yields null). `Targets/TargetIdentity.cs` (`SelectNewTargets`: stars-stripped name + ~1′) is the *add-time* skip — dropping a scanned target already in `KnownTargets` — not the collapse. Orchestration is `Forms/Presenters/MainForm.TargetLoadingPresenter.cs` — `GetImageLibraryTargets` / `GetJsonTargets` / `GetBrowsedTargets` / `GetDroppedTargets` → `ScanPathAsync` → `AddScannedTargets`.

### Selection VM (`State/TargetSelection.cs`)

Phase 2 of the SoC refactor (commit `1e1986d`). Observable view-model with three event-bearing properties: `KnownTargets`, `SelectedSingle`, `Checked` (HashSet) — events `KnownTargetsChanged` / `SelectedSingleChanged` / `CheckedSetChanged` fire only on actual change (reference equality for `SelectedSingle`, set equality for `Checked`). Mutators: `SetKnownTargets` / `AddKnownTargets` / `SetSelectedSingle` / `SetChecked` / `SetCheckedSet` / `SetAllChecked` / `AddKnownTarget` / `RemoveKnownTarget`. `AddKnownTargets` appends a load's new targets without touching `Checked` or `SelectedSingle` (loads accumulate); `SetKnownTargets` replaces the catalog and resets `Checked` to empty, now reached only by `Button_ClearAllTargets` emptying the list. **There is no `Mode` property** — render dispatch is explicit at the consumer: `Button_Graph` renders `SelectedSingle`, the multi-target graph auto-fires off `CheckedSetChanged` via the `mCheckedToggleDebounce` trigger in MainForm, and the two are independent views (clicking `Button_Graph` after checking boxes renders just the combo target; the next checkbox toggle re-renders the full checked set).

The form's `WireSelectionVm` subscribes the VM events to UI-update handlers (`OnVm*Changed`) and routes UI events into VM mutators (`OnCheckedListBoxItemCheck` / `OnCheckedListBoxSelectedIndexChanged` / `OnRightAscensionEdited` / `OnDeclinationEdited` / `Button_*Click`). The single `mUpdatingUiFromVm` flag short-circuits VM-driven UI writes so they don't re-enter the VM. **The legacy `mSuppressGraphModeEvents` / `mCheckedListBoxClickFiredHandler` flags + `WireGraphModeEvents` / `WireSingleMode` / `WireMultiMode` / `MarkSingleMode` / `MarkMultiMode` / `SyncTargetComboFromCheckedListBoxHighlight` helpers are gone.** The one remaining latch (`mCheckedListBoxJustToggled`) disambiguates ItemCheck-then-SelectedIndexChanged on the same user click — required because both fire when toggling a checkbox.

### Cache store (`Caches/`)

Caller-facing contract (invariants, threading, no-CT design, `EnsureAsync` semantics) lives at [`docs/design/cache-contract.md`](docs/design/cache-contract.md); the deep-dive below is the implementation narrative.

Phase 3 of the SoC refactor (commit `3425f8e`) plus the follow-on fit-cache completion (`c74224f`) plus Day-axis addition (`3e12470`) plus the 2026-05-17 pipeline-collapse refactor (Moon axis + `EnsureAsync` single entry, commits `cafbf3c` / `d4fe74c`). Eleven files:
- `MoonSweepSample` (`Caches/MoonSample.cs`) — public struct `(Utc, SepDeg, MoonAltDeg)`. Promoted from a private nested type in `AltitudeSeries`; renamed off `MoonSample` to avoid colliding with AL's `Astronomy.Core.Moon.MoonSample`.
- `NightCacheEntry` — public class holding per-target per-night precomputes (`Dusk` / `Dawn` / `LstDusk` / `LstDawn` / `AltDusk` / `AltDawn` / `TransitInNight` / `YearAlt` / `IsPolar` / `SentinelX` / `MoonSamples` / `MoonAgeDays`). Promoted to public.
- `TargetCacheEntry` — owns `Target` + `IReadOnlyList<NightCacheEntry>` (the 365-day series).
- `TargetFitEntry` — owns `Target` + `HdmKey` + `IReadOnlyList<NightFit> Nights` (the year array, index-aligned with `TargetCacheEntry.YearDays`) + `NightFit Tonight` (the single-night slot Day and Sky read for tonight). Tonight isn't `Nights[0]` because the year grid is anchored at the 1st of the current month, not at today; the cache holds them as separate fields. The `NightFit` struct itself carries `Ceiling / Floor / CenteredFloor` (all `double?` — Year reads `Floor`, Sessions reads all three) plus `StartUtc / EndUtc` + `CenteredStartUtc / CenteredEndUtc` (Day reads these off the `Tonight` slot for its HD-overlay window box; the Floor/Centered variants drive Day's Floor/Transit placement-strategy radio), plus `TransitUtc` (`DateTime?`, the analytic upper-transit instant for the night — independent of H/D/M, carried here because `NightFit` is the natural per-night slot Day's HD-overlay transit tick reads from). All fields are nullable; a fit-less night is `default(NightFit)` with every field null.
- `TargetTrajectoryEntry` — owns `Target` + `NightDate` + `DayWindowKey Window` + `IReadOnlyList<AltAzSample> Samples` (AL's `AltAzSample` carries `AltDegGeometric` + `AltDegApparent` + `AzDeg`). Built by `BuildTrajectoryAsync` which delegates to `AltitudeCurve.Sample(target, location, startUtc, 1min, count)` in AL — TP no longer maintains an inline per-minute `AltAz.At` sweep. Replaces the pre-2026-05-28 `TargetDayAltitudeEntry` (which carried `IReadOnlyList<double?> AltitudesPerMinute` with null = below-horizon sentinel; the new structure carries the full AltAz + apparent-altitude triple, sliced to the day window at paint time).
- `MoonEphemerisEntry` — owns `NightDate` + `DayWindowKey Window` + `IReadOnlyList<MoonSample> Samples` (AL's `MoonSample` is parallax-aware topocentric: `AltDegGeometric` + `AltDegApparent` + `AzDeg` + `DistanceKm` + `AgeDays` + `PhaseAngleDeg` + `IlluminatedFrac`). Singleton per night, target-independent; the moon is shared across all targets at a location. Built by `BuildMoonEphemerisAsync` which delegates to `MoonEphemeris.Sample(location, startUtc, 1min, count)` in AL. Day reads `Samples[i].AltDegGeometric` for its translucent moon overlay; Sky's K-S walk reads `Samples[i].AltDegApparent` (K-S contract is apparent-altitude). Replaces the pre-2026-05-28 `MoonAltitudeEntry` (geometric-only `IReadOnlyList<double>` with consumers re-applying `Refraction.SaemundssonDeg`).
- `NightDate` — `readonly record struct NightDate(DateOnly DuskDate)`. The local calendar date on which the night's astronomical dusk occurs, evaluated under the site's `TimeZoneInfo`. Replaced `DayWindowKey` on the cache surface 2026-05-28; aligns TP's cache shape with the planned IS Plugin (ISP) cache so the AL primitive surface is stable before ISP design starts. `NightDate.Of(NightWindow, TimeZoneInfo)` is the single derivation seam (returns `default(NightDate)` for invalid polar-night windows, which `EnsureAsync` treats as the skip sentinel — trajectory + moon prep no-op, year + fits still build). `DayWindowKey` survives only as the per-render X-axis bounds carried inside the cache entries' `Window` field; `ChartLayout.BuildDayWindow` is the single producer.
- `IChartCacheStore` — interface. **Primary public surface: `EnsureAsync(ctx, nightDate, progress = null) → ChartEvaluation`** — single pre-render pipeline that diffs `ctx` against `mLastEnsureCtx` and runs the necessary internal Prepare paths (`SetLocationAsync` if location-relevant fields changed, `PrepareMoonAsync` unconditionally when `nightDate` is valid since moon is target-independent, `PrepareManyAsync` / `PrepareFitsAsync` / `PrepareTrajectoryAsync` when targets are present), returning a `ChartEvaluation` (the Sky-brightness staleness gate). **Per-axis surface** (consumed by sub-charts on Render): **yearDays axis**: `GetOrNull(t)` / `PrepareManyAsync(targets, IProgress<int>? = null)`. **Fits axis**: `GetFitOrNull(t, HdmKey)` / `PrepareFitsAsync(targets, HdmKey, IProgress<int>? = null)`. **Trajectory axis**: `GetTrajectoryOrNull(t, NightDate)` / `PrepareTrajectoryAsync(targets, NightDate, IProgress<int>? = null)`. **Moon axis**: `GetMoonOrNull(NightDate)` / `PrepareMoonAsync(NightDate)`. The `Get*OrNull` are sync reads; the per-axis `Get*OrBuildAsync` builders are internal to `CacheAxis` (Tier 5, 2026-05-19) — only the cache's own `Prepare*` paths build. Lifecycle: `SetLocationAsync(newLocation, startingUtc)` (drain + reset all four axes + switch). **No `CancellationToken` parameters on any method** — stale work runs to completion and discards via a publish-time location check (see Cancellation policy below).
- `ChartCacheStore` — default implementation. The four cache axes (yearDays / fits / trajectory / moon) are each a generic `CacheAxis<TKey,TVal>` (`Caches/CacheAxis.cs`, Tier 5 2026-05-19) owning a store dict + an in-flight `Task` dict + the get / build / in-flight-dedupe / publish lifecycle on the shared `mGate`; stale builds discard at publish via a `Func<Location>` location check. The store owns the heavy `Task.Run`-backed compute paths, wired into the axes as `build` delegates: `ComputeYearDays` (the ~25,600-call-per-target moon-sample sweep — the yearDays axis), `ComputeNightFits` + `ComputeTonightFit`, both calling the shared `ComputeOneFit` recipe (per-night `BestSession.ResolveCandidates` + `PlaceBest` + `PlaceCentered` + `SessionAltitude.{Floor, Ceiling}` — the fits axis, with both the year array and the single-night Tonight slot built in one `BuildFitEntryAsync` pass; `BuildFitEntryAsync` reconstructs its `IHorizonProfile` from the `HdmKey`), `BuildTrajectoryAsync` (delegates to AL's `AltitudeCurve.Sample` for the per-minute target AltAz sweep — the trajectory axis), and `BuildMoonEphemerisAsync` (delegates to AL's `MoonEphemeris.Sample` for the per-minute moon ephemeris — the moon axis). The 2026-05-28 axis rekey shifted these two from `(Target, DayWindowKey)` and `DayWindowKey →` to `(Target, NightDate)` and `NightDate →`, aligning with ISP's planned cache shape and pulling the per-minute compute into AL primitives; `BuildDayWindowForDate(Location, NightDate)` is the cache-internal helper that resolves the chart-window UTC bounds from the night date (local-noon UTC anchor → `NightCalculator.ComputeNight` → `ChartLayout.BuildDayWindow`). One `ResolveCandidates` resolve drives both placements per night (~25% fewer Meeus calls than the old separate Year / Sessions paths). **No cancellation infrastructure** — `mLocationCts` / `WithExternalCancel` removed in the cache-completion pass; in-flight stale builds are detected at publish via `ReferenceEquals(mLocation, location)` and silently discarded. `mLastEnsureCtx: ChartContext` field tracks the most-recently-applied snapshot for `EnsureAsync`'s diff logic; `LocationCacheEquivalent` (value-compares Lat/Lon/North/West/Elevation/DateTime.Date/year-start-day) lives on the cache as a private static and gates `SetLocationAsync` so form-side `Location.With(...)` reassignments with identical values don't thrash the cache.

`HdmKey` (`State/HdmKey.cs`) — readonly struct keying the fits cache. Fields: `HorizonDeg`, `DurationTicks`, `ActiveFilter` (the `Filters.Filter` record — structural equality, so a Lorentzian scrub that yields the same field values compares equal and skips a rebuild), `MoonAvoidanceEnabled` (bool master toggle), `LocalHorizon` (the polyline / obstruction profile reference; reference-identity-compared, null for the scalar case, where `HorizonDeg` differentiates). Surfaced as `ChartContext.Hdm` (derived property — pulls every field from `ctx.Policy`). Bortle / ExtinctionK are intentionally excluded — they affect Sky's K-S brightness path, not fit decisions, and ride the coordinator's post-apply hook instead of forcing a fit rebuild.

`MainForm` instantiates `mCache = new ChartCacheStore(mLocation, mObservation.Utc)` before the sub-charts (the seed UTC anchors the warmup-path night cache), threads the cache reference into each sub-chart's `Render(...)` call, and after each NINA load fires `_ = Task.Run(async () => { await mCache.PrepareManyAsync(allLoaded); await mCache.PrepareFitsAsync(allLoaded, currentHdm); })` for background warmup (trajectories are warmed lazily on the first Day-area Apply via `PrepareTrajectoryAsync` since the night window depends on the picker-driven date). `Button_Graph_Click` funnels through `RunGraphBuildAsync`, which calls `await mCoordinator.ApplyImmediateAsync(ctxSnapshot)` with no per-call progress argument — progress ticks come from the `CreateChartProgress` factory wired once at coordinator construction, driving `ProgressBar_Processing` for every Apply path uniformly. Location-edit paths route through `LocationsCacheEquivalent` (compares Lat / Lon / North / West / Elevation / `NightCache.ComputeYearStartDay`) and call `mCache.SetLocationAsync` only when geometry actually changed — Horizon / Duration scrubs preserve the year-cache but invalidate the fits cache via a new `HdmKey`; pure picker-driven scrubs preserve fits but build a fresh trajectory-cache entry under the new `NightDate`.

### Orchestration layer (`State/ChartContext.cs`, `State/ChartEvaluation.cs`, `State/ChartCoordinator.cs`)

Phase 1 + Phase 2 of the orchestration-layer refactor (commits `b98912e` / `a267716` /
follow-on Phase 3), then the 2026-05-17 pipeline-collapse refactor (`cafbf3c` →
`07f49f0`). MainForm used to be the orchestrator-by-accident — every UI handler embedded
its own decision tree about what to invalidate, which debounce to restart, which
suppression flag to set, which sub-chart to refresh. Adding a control meant re-deriving
all of that. Then the coordinator pulled the dispatch into a single place but still owned
a per-area diff table + 3-way `Render` / `RefreshVisibility` / `ShowOnly` branching that
accreted special cases. Now the **cache** is the staleness gate; the coordinator is a
thin generation-bumped pipeline:

- **`ChartContext`** — sealed `record` snapshotting all chart-pipeline inputs:
  `Location` (the observer site — geometry + `TimeZoneInfo` + `BortleClass` /
  `ExtinctionK` + the `LocalHorizon` terrain profile; Phase 2 stripped the
  observation moment and the planning scalars off `Location`), `Targets` (the
  effective render set), `Policy` (the `PlanningPolicy` record — `TargetFloorDeg` /
  `MinDuration` / `ActiveFilter` / `MoonAvoidanceEnabled` / `IHorizonProfile LocalHorizon`,
  plus the derived `MoonProfile` property — null unless the master toggle is on and a
  filter is active),
  `Observation` (the `ObservationMoment` `(Utc, Zone)` carrier), `ActiveArea`,
  `TargetColors` (the per-target color palette dict, owned by MainForm so
  Add/Remove flows can mutate consistently without re-snapshotting), `DayMode`
  (`Floor` / `Transit` — Day chart's placement-strategy radio). Built by `MainForm.SnapshotCurrent(targets)` (or the no-arg
  `SnapshotCurrent()` which pulls `Targets` from `mCoordinator.LastAppliedTargets`) at
  one point in time and threaded through every Render call so downstream code can't
  observe state drifting mid-render. The derived `Hdm` property aggregates the five
  fields that key the fits cache — `ctx.Hdm` is what the cache stores against and what
  sub-charts pass to `GetFitOrNull`.

- **`ChartEvaluation`** — record returned by `EnsureAsync`, carrying three fields:
  `BrightnessInputsChanged` (consumed only by the coordinator's post-apply hook, which
  gates the Sky K-S re-walk; not threaded through sub-chart `Render`), plus `EnsureWork`
  and `RenderWork` — the cache's pessimistic per-target-per-axis tick counts for the
  cache-prep phase and the sub-chart Render phase respectively, used to size the
  progress-bar offset between `EnsureAsync`'s prepare work and `Render`'s per-target
  ticks. The Tier-3 sweep
  (2026-05-19) dropped the four diag-only axis flags, the three zero-read keys, and the
  dead `eval` parameter on `Render` — see the `ChartEvaluation` glossary entry in
  CLAUDE.md. Phase 7's per-sub-chart short-circuit was shipped (`97f5dc2`) then reverted
  (`759f968`) on LC2 paint instability across hidden→visible `Control` transitions.

- **`ChartCoordinator`** — thin funnel. Public surface: `Apply(ctx, progress=null)`
  (debounced 150 ms internally), `ApplyImmediateAsync(ctx, progress=null)` (no-debounce,
  awaitable), `Cancel` (stops the debounce; no in-flight cancellation — see below),
  `Dispose`. State is minimal: `mGeneration` (monotonic counter that drives supersession),
  `mLastAppliedTargets` (pre-stamped at pipeline entry so concurrent `Apply()`'s no-arg
  `SnapshotCurrent()` reads the user's current intent), `mPendingContext` +
  `mPendingProgress` (most recent debounced Apply, drained on tick). Pre-2026-05-17 the
  coordinator also held `mLastAppliedByArea` + `mEverRendered` for the per-area
  diff/dispatch table; both collapsed when `EnsureAsync` became the single staleness
  gate.

  Pipeline flow (`RunPipelineAsync`):
  1. Capture `gen = Interlocked.Increment(ref mGeneration)` at entry. Pre-stamp
     `mLastAppliedTargets = ctx.Targets` so a concurrent `Apply()` reads current intent.
  2. Derive `nightDate` via `NightCalculator.ComputeNight(ctx.Location, ctx.Observation.Utc)`
     → `NightDate.Of(night, ctx.Observation.Zone)` (always fresh, never reads
     `mCache.LocationNightCache` — pre-`SetLocationAsync` that's the OLD location's night,
     and the resulting OLD `nightDate` would mismatch the sub-chart's post-`SetLocationAsync`
     NEW `nightDate`, causing every `GetTrajectoryOrNull` / `GetMoonOrNull` to miss and
     targets to vanish from Day. Caught by the post-collapse regression at `ac1e40e`;
     `NightCalculator.ComputeNight` is sub-millisecond Meeus so the redundant compute is
     cheap insurance. `NightDate.Of` returns `default(NightDate)` for invalid polar-night
     windows, which `EnsureAsync` treats as the skip sentinel).
  3. `await mCache.EnsureAsync(ctx, nightDate, progress)` — single staleness gate. Inside,
     the cache diffs `ctx` against `mLastEnsureCtx`, calls `SetLocationAsync` if
     Location-relevant fields changed (`LocationCacheEquivalent` value-compare),
     `PrepareMoonAsync` always when `nightDate` is valid (target-independent), and
     `PrepareManyAsync` / `PrepareFitsAsync` / `PrepareTrajectoryAsync` when targets are
     present. The returned `ChartEvaluation.EnsureWork` / `RenderWork` let the coordinator
     wrap `Render`'s per-target progress ticks at the correct offset on the shared bar.
  4. **Generation guard**: if `gen != Volatile.Read(ref mGeneration)` (a newer Apply has
     come in while we awaited) → return without writing any state.
  5. `mRenderActiveArea(ctx)` — call the active sub-chart's Render via
     `MainForm.RenderArea`. Render runs unconditionally (no short-circuit dispatch
     anymore — Phase 7 reverted).
  6. `mPostApplyHook(ctx, eval)` — `RefreshAstrometryLabels` + `UpdateNowLine` +
     `UpdateHorizonLine` on every sub-chart + `PushSkyKSInputs(ctx)` for Sky's K-S walk
     (Bortle / ExtinctionK / Filter changes ride here without forcing a fit recompute).

  Supersession: instead of CTS-based cancellation, the coordinator uses the generation
  counter (`Interlocked.Increment` write + `Volatile.Read` guard for fence safety even
  if Apply were ever invoked off-thread). Multiple pipelines may overlap during rapid
  scrubs (each captures its own `gen` at entry); the cache's per-(target, key) in-flight
  dedupe ensures the heavy compute isn't duplicated. When the older pipeline's awaits
  resolve, its generation-guard check causes it to bail before any side-effecting Render
  or post-apply call. Only the latest Apply's pipeline ever writes chart state. No
  exceptions thrown, no try/catch needed for supersession. Form-lifecycle cancellation
  (close while warmup is in flight) is the one remaining CTS — owned by MainForm as
  `mFormClosingCts`, observed only by `StartCacheWarmup`'s `PrepareManyAsync` /
  `PrepareFitsAsync` race (the NINA-load warmup chain in
  `MainForm.TargetLoadingPresenter.cs`) for clean shutdown; `PrepareTrajectoryAsync` /
  `PrepareMoonAsync` don't observe it.

- **`MainForm.SnapshotCurrent(targets)`** — single point that reads `mLocation` /
  `mObservation` / `mPlanningPreferences` / `mActiveFilter` /
  `CheckBox_Moon_AvoidanceEnable.Checked` / `mLocalHorizon` / `SelectedArea()` /
  `mTargetColorsByTarget` / `mDayChartMode` and synthesizes a `PlanningPolicy` (via its
  primary constructor + object initializer, composing `mLocalHorizon` with a fresh
  `ScalarHorizonProfile(mPlanningPreferences.TargetFloorDeg)` through `MaxOfHorizonProfile`
  when a polyline horizon is loaded) into a `ChartContext`. The no-arg overload
  `SnapshotCurrent()` reads `Targets` from `mCoordinator.LastAppliedTargets ??
  Array.Empty<Target>()` so radio handlers / picker scrubs / sort changes don't need
  to thread a parallel target list. Adding a new chart input is one record-field
  addition + one read here.

- **`RenderArea(ctx, progress)`** (`Forms/Presenters/MainForm.ChartBuildPresenter.cs`) —
  four lines that own the per-Render visibility + paint trigger: `sc.Render(ctx, mCache,
  progress)` (build/update Series state), `ShowOnlyAltitudeChart(sc.Control)` (flip
  Visible per radio), `ResizeAltitudeChartArea(sc.IdealHeight)` (elastic panel resize),
  `sc.Control.Refresh()` (synchronous repaint). The Refresh after `Visible=true` is load-bearing for the moon
  overlay's first paint after a hidden→visible cycle — LC2's SKControl drops Fill-only
  `LineSeries` from its paint output without the kick. Diagnosed via the Sky moon
  overlay rendering fine across the same scrub sequence (Sky was visible during scrubs
  so LC2's paint cache stayed hot); fix is at the dispatch layer so every sub-chart
  benefits uniformly. See ROADMAP "2026-05-17" entry for the diagnostic walk.

UI handlers reduce to: build snapshot, hand to coordinator. A handful of paths still
have ancillary work (e.g. `Button_Now_Click` snaps the date/time pickers; `OnLocationEdited`
flips combo to "Custom"; `RunGraphBuildAsync` awaits the coordinator's `ApplyImmediateAsync`,
whose progress bar is driven by the coordinator's `CreateChartProgress` factory rather than a per-call wrap),
but the downstream cache + render dispatch is all coordinator-owned.

**Remaining legacy debounce:** `mSessionsRebuildDebounce` / `RestartSessionsRebuildDebounce`
/ `SessionsRebuildDebounce_Tick` exist solely for the `OnLocationEdited` keying-change
detection. Per the user spec, lat/lon/elev scrubs that cross `LocationsCacheEquivalent`
should clear the checked set + blank the chart (`ResetForLocationChange`), not auto-render
at the new geometry. Doing that decision per spinner tick is wrong (each intermediate
tick would clear checkboxes); doing it on the coordinator's debounce tick is also wrong
(the coordinator doesn't know about checkbox semantics). So `OnLocationEdited` keeps a
narrow 150 ms debounce whose tick decides between `ResetForLocationChange` (keying drift)
and `mCoordinator.ApplyImmediateAsync` (within-equiv scrubs that ride OnLocationEdited
— Bortle / ExtinctionK).

### Universal chart behavior contract

Every chart sub-area (Day / Sky / Year / Sessions; any future chart) MUST implement `IAltitudeSubChart`. The interface enforces the contract at compile time — forgetting any member on a new sub-chart is an error. Behaviors:

1. **Live now-line update.** `UpdateNowLine(DateTime now)` mutates the red section's X position in place (no data recompute). MainForm's moment handlers (`DatePicker_ValueChanged`, `Button_Now_Click`) iterate `foreach (var sc in mSubCharts.Values) sc.UpdateNowLine(when)`. No debounce — instant feedback.

2. **Live horizon-line scrub.** `UpdateHorizonLine(double horizon)` mutates the green section's Y position in place. `NumericUpDown_TargetFloor_ValueChanged` iterates the same way. Sky has no horizon line and the method is a no-op there; every other sub-chart implements it.

3. **Hide-on-no-fit on H/D/M scrub** (the "universal" hide rule). When the active Horizon, Duration, or MoonAvoidanceProfile leaves a target with no D-hour fit, the target's curve is hidden on every chart simultaneously. Each chart hides differently; **all fit decisions live in the cache, never in the sub-charts** — Day and Sky both read tonight off `TargetFitEntry.Tonight`, Year and Sessions both read per-night off `TargetFitEntry.Nights[i]`. Single source of truth for the fit decision:
   - **Day** (single-night view, fit-tonight-only): per-target. Targets with `Tonight.Floor` null are excluded from `mChart.Series` and the legend entirely (not just alpha-0). Tonight's `StartUtc / EndUtc / Floor` drive the HD-overlay window box. Per-minute altitudes come from `cache.GetTrajectoryOrNull(target, nightDate).Samples[i].AltDegGeometric`. H/D/M scrubs hit the coordinator → `hdmKeyChanged` → full Render after `PrepareFitsAsync` (which builds both year array + Tonight slot in one pass).
   - **Sky** (single-night view): per-target. Stroke alpha → 0 when `Tonight.Floor` is null; restore palette alpha otherwise. Same `cache.GetFitOrNull(target, ctx.Hdm)?.Tonight` lookup as Day — Day and Sky agree on which targets are visible tonight by construction since they share the cached fit. Sky's K-S magnitudes are walked inline (filter-dependent) but the fit-gate that toggles visibility is cache-driven.
   - **Year** (12-month view): per-target × per-night. `ObservablePoint.Y` → null (line break) for unfit nights; for fit nights, Y is `NightFit.Floor` read directly from `cache.GetFitOrNull(target, ctx.Hdm)?.Nights[i]`. `ChartCacheStore.ComputeNightFits` runs the `BestSession.ResolveCandidates` + `PlaceBest` + `SessionAltitude.Floor` walk under each `HdmKey`, the coordinator awaits `PrepareFitsAsync(targets, ctx.Hdm)` before dispatching Render, and the sub-chart paints synchronously.
   - **Sessions** (12-month view, three curves): per-target × per-night × three. `NightFit.Ceiling` / `Floor` / `CenteredFloor` read straight off `Nights[i]`. The shared-resolve optimization (one `ResolveCandidates` drives both `PlaceBest` and `PlaceCentered`) lives in `ChartCacheStore.ComputeNightFits`, not the sub-chart.

   M (the Moon component) covers EVERY input that mutates `mMoonAvoidanceProfile`:
   - Active filter selection (`SetActiveFilter` calls `Filter.ToProfile()` which builds a fresh `MoonAvoidanceProfile`).
   - Lorentzian relaxation parameters (`OnLorentzianControlChanged` reads `BuildProfileFromControls()`).
   - Moon avoidance enable checkbox (`CheckBox_Moon_AvoidanceEnable` toggles between profile and `null`).

   All three converge through `mCoordinator.Apply(SnapshotCurrent(mLastRenderedTargets))` (150 ms internal debounce). The coordinator's pipeline detects the change as an `HdmKey` flip, awaits `PrepareFitsAsync` for the new key, then renders the active sub-chart synchronously from the just-built cache entries. The post-apply hook calls `PushSkyKSInputs(ctx)` to re-walk Sky's K-S grid. Bortle / ExtinctionK changes don't move `HdmKey` (they're Sky-K-S inputs, not fit inputs) and ride the post-apply hook only — no fit recompute fires.

4. **First-paint visibility.** `Render(...)` reads `cache.GetFitOrNull(target, ctx.Hdm)` directly — the initial paint already reflects current H/D/M with no "show all, then hide" flicker. The coordinator's `PrepareFitsAsync` await before Render guarantees fits for the current `HdmKey` are built (or in-flight; an in-flight build for the same key is awaited via the cache's per-(target, key) dedupe).

5. **Sort changes route through the coordinator.** `Reorder` was dropped from the interface in PR-3 of the architectural-review campaign; sort changes call `mCoordinator.Apply(SnapshotCurrent(sorted))` with the permuted target list. The coordinator's pipeline runs (Render fires) but the cache stays warm because the target SET is unchanged — only the order in `mChart.Series` rebuilds, all per-target altitudes / fits / moon data come straight from cache.

6. **No sub-chart cancellation infrastructure.** Sub-charts are render-only synchronous painters — there is no `CancellationTokenSource`, no `Task.Run`, no `BeginInvoke`. The cache owns all the async compute and dedupes per (target, key); a closing form orphans any in-flight cache builds, which discard themselves at publish via the `ReferenceEquals(mLocation, location)` check.

7. **Sub-charts always Render** (post-2026-05-17). Phase 7's per-sub-chart short-circuit on `eval` flags was shipped (`97f5dc2`) then reverted (`759f968`) when LC2's paint state across hidden→visible `Control` transitions proved unstable even with identical Series/Values data. The Render-runs-unconditionally rule + `Control.Refresh()` after `Visible=true` in `MainForm.RenderArea` is the load-bearing combo for paint correctness across radio swaps. `mLastTargets` fields on sub-charts are scaffolding for a future smarter short-circuit; don't be surprised they're set-but-unread.

When adding a new sub-chart, the pattern is: implement `IAltitudeSubChart`, add an entry to `mSubCharts` in `InitializeDynamicControls`. If the sub-chart needs H/D/M-dependent precompute, extend `NightFit` / `ChartCacheStore.ComputeNightFits` rather than introducing a per-sub-chart bg task. The foreach loops in MainForm pick the new sub-chart up automatically. The interface IS the contract.

### Moon avoidance

Per-night Lorentzian-driven moon-clear evaluation gates the Day-chart HD Overlay, the Sessions placement candidates, and the universal hide-on-no-fit rule across every chart. User-facing UX (Enable checkbox, filter library, Edit Filters dialog, `*` indicator, right-click-to-edit) in [README.md](README.md#filters--moon-avoidance). MoonAvoidanceProfile is owned by MainForm (`mMoonAvoidanceProfile`) and threaded into each sub-chart's `Render(...)` call via `ChartContext.Policy.MoonProfile`. `BestSession.ResolveCandidates(...)` (Library) returns visibility ∩ moon-clear in one call so Sessions's PlaceBest + PlaceCentered see identical inputs.

Moon avoidance is committed and active end-to-end. Post-NINA-load warmup runs in **~1-2 sec for 44 targets** (yearDays via `PrepareManyAsync`) plus a few seconds for the per-`HdmKey` fit build (`PrepareFitsAsync`) chained behind it; both fire in a single `Task.Run` so the user's first Sessions / Year click hits a fully warm cache. Down from ~17 min pre-CoordinateSharp-removal; halved again 2026-05-04 by the `MoonSeparation.ObserveAt` single-pass dedup, the `ObserverInfo` class→struct conversion, and the `MoonPosition` periodic-table flatten — see `Astronomy.Core.Benchmarks/HotPathBenchmarks.cs` for the BDN baseline. The 1-min `MoonSeparation.ObserveAt` sweep populates `entry.MoonSamples` (a `List<MoonSweepSample>`) per night per target.

### K-S sky brightness (Sky chart area)

User-facing UX in [README.md](README.md#sky-brightness). Implementation: `Astronomy.Core.Brightness.SkyBrightness.KsAt(...)` (closed-form Krisciunas–Schaefer 1991, mag/arcsec², lower = brighter) takes dark-sky baseline V₀ as a caller-supplied parameter, composing it with solar twilight from `Brightness.Twilight.ZenithBrightening(sunAlt)` and moon contribution; the Sky sub-chart is the caller that resolves V₀ via `Brightness.Bortle.DefaultZenithMag(BortleClass)` before invoking `KsAt` — `DefaultZenithMag` is not called inside `KsAt` itself. Per-Location `BortleClass` + `ExtinctionK` drive baseline + extinction; the surfacing `ComboBox_Bortle` + `NumericUpDown_LocalExtinction` are designer-resident inside `GroupBox_Location`. Active filter's `CenterNm` scales k via Rayleigh λ⁻⁴ in `SkyBrightness.ScaleK`. The Sky sub-chart's Y axis uses data-inversion (`plotY = SkyAxisMinMag + SkyAxisMaxMag - mag`) plus a custom `Labeler` that maps each plot value back to its actual magnitude — so brighter sky renders higher while the X axis stays at the visual bottom (no `IsReversed`). K-S is additive on top of the universal hide rule (Sky targets hidden by hide-on-no-fit get alpha 0 stroke; the K-S magnitudes are still computed but invisible). Bortle / ExtinctionK / Filter scrubs ride `OnLocationEdited` → `SessionsRebuildDebounce_Tick` → `mCoordinator.ApplyImmediateAsync(SnapshotCurrent())`; the coordinator's post-apply hook calls `PushSkyKSInputs(ctx)` which reads `Astronomy.Core.Brightness.SkyBrightness.BWRefNm`-defaulted `active = ctx.Policy.ActiveFilter` and pushes both `active.CenterNm` and `active.BandwidthNm` into `mLC2Sky` (`ActiveFilterCenterNm` / `ActiveFilterBandwidthNm`) before re-walking `RefreshSkyBrightness(...)`. `LocationsCacheEquivalent` deliberately does NOT include Bortle / ExtinctionK so a sky-brightness scrub doesn't drop the year-cache; Bortle / ExtinctionK aren't in `HdmKey` either so no fit recompute fires — Sky's K-S grid is the only thing that re-walks. Tests in `Astronomy.Core.Tests/Tests/SkyBrightnessTests.cs`.

### Filter / moon-avoidance implementation

Filter / moon-avoidance implementation lives at the call sites. Class docs on `Filters/Filter.cs` (immutable POCO, `ToProfile()` drops Name/CenterNm/BandwidthNm — Lorentzian is wavelength-agnostic, CenterNm reserved for K-S, BandwidthNm reserved for IS), `Filters/FilterLibrary.cs` (persistence at `%APPDATA%\TargetPlanner\filters.json`, `BuiltinDefaults` for the H/O/S/L/R/G/B factory set, `MigrateLegacyFields` auto-fills CenterNm=0 entries, `DiffersFromBuiltinDefault` drives the `*` indicator), and `Forms/EditFiltersForm.cs` (modal, no Designer file, `BindingList<FilterRow>` shadow, per-row Defaults button, validates name on Save). MainForm field comments at `mFilterLibrary` / `mSuppressFilterEvents` / `mEditFiltersDialogOpen` / `mFilterAutoSaveDebounce` / `mFilterRadios` explain the auto-save target, the WriteProfileToControls suppression, the dialog-mode suppression, and the parallel-indexed sync invariant. Method comments on `BuildFiltersMenu` / `BuildFiltersGroupBox` / `SetActiveFilter` / `OpenEditFiltersDialog` / `OnLorentzianControlChanged` / `RefreshFilterMenuLabels` cover the early-init bypass (avoids restarting SessionsRebuildDebounce while year caches are mid-flight), the right-click-to-edit hook, and the post-dialog re-resolve. **Layout fact (Designer-only):** `GroupBox_Moon_Filters` is a child of `GroupBox_MoonAvoidance` (nesting is `GroupBox_Target` > `GroupBox_MoonAvoidance` > `GroupBox_Moon_Filters`); `CheckBox_Moon_AvoidanceEnable` (the master gate) also lives inside `GroupBox_MoonAvoidance`, as a sibling of `GroupBox_Moon_Filters`.

### UI flow (`Forms/MainForm.cs`)

- `InitializeDynamicControls` instantiates `mCache = new ChartCacheStore(mLocation, mObservation.Utc)`, assigns the two typed sub-chart fields (`mLC2Day = new AltitudeSubChart_Day()`, `mLC2Sky = new AltitudeSubChart_Sky()`), then builds `mSubCharts = {"Day": mLC2Day, "Sky": mLC2Sky, "Year": new AltitudeSubChart_Year(), "Sessions": new AltitudeSubChart_Sessions()}`. A foreach loop adds each sub-chart's `Control` to `Panel_AltitudeChart` and subscribes `IdealHeightChanged`. Fires `_ = GetImageLibraryTargets(...)`, calls `WireSelectionVm`, seeds the `local-targets.json` sidecar into `KnownTargets`, and returns. **No startup chart auto-build** — `Button_Graph_Click` is the only render path. The chart panel paints empty sub-charts until the user clicks Graph.
- Coordinate inputs are triple-bound (D/M/S `NumericUpDown`, decimal `TextBox`, N/S/E/W checkbox) via `Support/CoordinateInput.cs`. The helper owns all the "update one surface and keep the others in sync" plumbing through a single `mSuppress` flag — callers never unsubscribe / re-subscribe sibling events. Four instances: `mLatitudeInput`, `mLongitudeInput`, `mRaInput`, `mDecInput`. RA/Dec edits route through `OnRightAscensionEdited` / `OnDeclinationEdited` (in `Forms/Presenters/MainForm.CoordinatePresenter.cs`), which call `mSelection.SetSelectedSingle(currentTarget.With(...))` — the VM is the source of truth for the active target.
- **Time control is sampled, not live.** `mObservation` (an `Astronomy.Core.Time.ObservationMoment` carrying UTC + the site `TimeZoneInfo`) is the single source of truth for "when the user is planning for." `SnapMomentToNow` samples wall-clock-now at the site -- called by `Button_Now_Click` and the startup constructor. `DatePicker` changes carry the existing site-local time-of-day forward onto the new picked date via `UpdateLocalDateTimeEvents`, so the moment behaves as "selected date at the time I last said Now." No `TimePicker`, no 5-second poll timer, no "live now vs. held" radio / checkbox trio.
- `Button_Graph_Click` renders the single combo target. It stops the multi-graph debounce (an explicit "single now" intent), resolves `ComboBox_SelectTarget.Text` to a `Target` and — only when a match is found — pushes it via `mSelection.SetSelectedSingle` (the conditional preserves whatever `SelectedSingle` already is when the combo text doesn't resolve), then reads `mSelection.SelectedSingle` and, if non-null, calls the shared `RunGraphBuildAsync(new[] { current })`; if null it shows a 2-second `ShowTransientMessage("No Targets")`. The multi-target (checked-set) path is independent: toggling a `CheckedListBox_SelectedTargets` checkbox fires `CheckedSetChanged` → the `mCheckedToggleDebounce` timer → `CheckedToggleDebounce_Tick` → `RunGraphBuildAsync(checkedTargets)`. `RunGraphBuildAsync` is the shared build entry both paths funnel through: it builds the snapshot via `SnapshotCurrent(targets)`, then `await mCoordinator.ApplyImmediateAsync(ctxSnapshot)` with no per-call progress argument — progress ticks come from the `CreateChartProgress` factory wired once at coordinator construction, driving the progress bar uniformly for every Apply path. The coordinator's pipeline owns cache prepare + render + post-apply hook; the radio handlers reduce to `mCoordinator?.Apply(SnapshotCurrent())`.
- `Button_BrowseTargetList_Click` runs `GetBrowsedTargets`: a multi-select `OpenFileDialog` (`PromptForFilesOrFolder`) returns either a set of `.json`/`.xisf` files or a single folder; `LoadFromPathsAsync` scans each (a folder recursively, both formats) and `AddScannedTargets` adds whatever is new. One-off — the path is not persisted. Drag-drop onto `CheckedListBox_SelectedTargets` (`OnTargetListDragDrop` → `GetDroppedTargets`) goes through the same `LoadFromPathsAsync`.
- `NumericUpDown_TargetFloor_ValueChanged` (Horizon) / `NumericUpDown_TargetDuration_ValueChanged` update `mPlanningPreferences` (and mirror it back onto the active `NamedSite.Preferences` via `PersistPlanningPreferencesToActiveSite` so the close-time save persists the latest spinner value), push the immediate horizon-line position to every sub-chart (Horizon only — instant feedback during scrub), and call `mCoordinator?.Apply(SnapshotCurrent())`. The coordinator's 150 ms debounce coalesces rapid scrubs; the pipeline's HdmKey-flip path awaits `PrepareFitsAsync` for the new key, then renders the active sub-chart from the freshly-built cache entries.
- **Presenter file splits.** `Forms/Presenters/` holds fifteen partial-class files carrying MainForm code (smaller ones include `AstrometryLabelsPresenter`, `ProgressBarPresenter`, `TransientNoticePresenter`, `AppMenuPresenter`, `ChartCoordinatorPresenter`, `CheckboxTintPresenter`, `ObservationMomentPresenter`, `SelectionCommandsPresenter`); the largest / most load-bearing clusters:
  - `MainForm.SortPresenter.cs` — `SortedTargets` / `ResortSelectedTargets` / `PopulateTargetComboFromTargets` / `PopulateCheckedListBoxFromTargets` + the `TargetRow` wrapper. Sort-and-populate plumbing.
  - `MainForm.CoordinatePresenter.cs` — `OnLatitudeEdited` / `OnLongitudeEdited` / `OnRightAscensionEdited` / `OnDeclinationEdited` callbacks + `SyncLocationUIFromModel` / `SyncTargetUIFromModel` model→UI sync methods.
  - `MainForm.FilterMenuPresenter.cs` — the ~16-method filter/moon-avoidance cluster (`BuildFiltersMenu`, `SetActiveFilter`, `SaveActiveFilter`, `OpenEditFiltersDialog`, etc.).
  - `MainForm.TargetLoadingPresenter.cs` — the three Load/Browse button handlers + drag-drop, `ScanPathAsync` + `LoadFromPathsAsync` + `AddScannedTargets` (the funnel), `StartCacheWarmup`, the file/folder pickers.
  - `MainForm.SelectionVmPresenter.cs` — `WireSelectionVm`, the four `OnVm*` handlers + the two `OnCheckedListBox*` handlers (VM↔UI sync), `RebuildTargetColors` / `RecomputeDupeSetColors`, the listbox tint callbacks (`GetDupeRowBackground` / `GetCheckboxInteriorTint`), and the right-click visible-tonight clear.
  - `MainForm.ChartBuildPresenter.cs` — the chart-build cluster: Graph + CheckedTargets buttons + `RunGraphBuildAsync` (the shared single/multi entry), `CheckedToggleDebounce_Tick`, `HarvestCheckedTargets`, `SelectedArea` + `RenderArea` (the coordinator's post-await render delegate), the chart-area UI (`ShowOnlyAltitudeChart` / `OnSubChartIdealHeightChanged` / `ResizeAltitudeChartArea`), the four radio `CheckedChanged` handlers, and `PushSkyKSInputs` (the coordinator's post-apply Sky K-S brightness push).

  These are partial-class file splits, not real Presenter objects: each cluster orchestrates 6+ form controls + the VM + the coordinator and constructor-injecting all of that was heavier ceremony than the relocation. The goal is a navigable `MainForm.cs`, not an object-graph refactor.
- **Location-edit funnel.** `OnLocationEdited` is the single attachment point for every user-driven location field edit (lat/lon spinner via `OnLatitudeEdited`/`OnLongitudeEdited`, the elevation spinner via `NumericUpDown_LocalElevation_ValueChanged`, the N/W flip checkboxes). It (1) calls `RefreshAstrometryLabels()` so the dawn/dusk/sun-altitude/moon-altitude/moon-rise-set/illumination labels update in real time, and (2) calls `RestartSessionsRebuildDebounce()` so the coordinator's `ApplyImmediateAsync(SnapshotCurrent())` fires after 150 ms idle — `EnsureAsync` then dispatches `SetLocationAsync` + the per-target Prepare chain based on its own `LocationCacheEquivalent` diff, and Render paints the active sub-chart. `ComboBox_Location_SelectionIndexChanged` invalidates the cache + refreshes labels immediately (single-shot user intent). `LocationCacheEquivalent` (on the cache) compares Lat/Lon/North/West/Elevation/`ComputeYearStartDay` so Horizon/Duration scrubs don't drop the cache.
- **`RefreshAstrometryLabels()`.** Reads `NightWindow` from `mCache?.LocationNightCache?.Starting` (with `NightCalculator.ComputeNight(mLocation)` fallback for early-init before `mCache` exists), then computes the five non-cached values inline — Sun altitude via `SunPosition.AltAzAt`, Moon altitude / phase via `AstroUtil`, Moon rise / set via `AstroUtil.GetMoonRiseAndSet` — and writes the eight static-info labels. ~150 µs of Meeus work + 8 string assignments, fast enough to fire on every spinner tick without debouncing. Called from `UpdateLocalDateTimeEvents` (DatePicker/TimePicker/Button_Now), `OnLocationEdited`, `ComboBox_Location_SelectionIndexChanged`, and the coordinator's post-apply hook. The 2026-05-17 deletion of `Support/AstrometryUi.cs` (commit `796d92d`) eliminated the parallel-compute path that was running its own `NightCalculator.ComputeNight(location)` on every spinner tick — cache is now the single source of truth for `NightWindow` data across both form labels and chart rendering.
- **`PickStartupLocation()` boots to `mAppSettings.LastSelectedLocationName`** when present in `mAppSettings.NamedLocations` (else first preset, else `Location.Default`). `settings.json` seeds this to "Penns Park" on first run; every `ComboBox_Location` pick overwrites it, so TP relaunches onto the most-recently-active site. Behaviour change 2026-05-19 — pre-collapse it pinned to a fixed personal-default regardless of last selection.
- **`File → Defaults` submenu (`Forms/MainForm.cs`).** Replaced `Clear All Data` in the 2026-05-19 settings collapse. `Edit settings.json` (`HandleEditDefaultsClick`) flushes in-memory `AppSettings` to disk, launches the OS-default editor on `settings.json` via `Process.Start` `UseShellExecute`, sets `mSuppressFormClosingSave`, and exits TP so the close-time save can't clobber the user's hand-edits — relaunch applies them. `Clear (factory reset)…` (`HandleClearDefaultsClick`) confirms, best-effort-deletes `settings.json` + `filters.json` + `local-targets.json` + the entire `%APPDATA%\TargetPlanner\Logs\` directory (recursive — `tp.log` + `.prev` + `screenshots/` + `screenshots.prev/`), sets `mSuppressFormClosingSave`, and exits. If a new persisted file is added, extend the Clear wipe list. Current public path properties: `Log.LogFolderPath`, `SettingsStore.FilePath`, `FilterLibrary.DefaultPath`, `LocalTargetStore.FilePath`.
- **`Help → Feedback → Open Notes Folder`** (added programmatically in `InitializeDynamicControls` since the Designer file is don't-touch). Launches Explorer on `%APPDATA%\TargetPlanner\Logs\`. Tooltip on the Feedback parent explains the Ctrl+N diagnostics feature for discoverability.
- **`Ctrl+N` opens (or focuses) the diagnostics dialog** (`Forms/DiagnosticsDialog.cs`, renamed from `UserObservationDialog` 2026-06-11; `USER_OBS_*` log markers keep their names). MainForm.ProcessCmdKey intercepts the hotkey. Modeless + TopMost dialog, notes-only since 2026-05-19 (the 12-item checklist was dropped — only the free-form notes carried debug signal). User writes free-form notes while still interacting with the main chart. OK writes a self-contained `USER_OBS_END` line to `tp.log`: the notes (empty/whitespace encodes as `notes="(checkpoint)"` so `grep checkpoint` finds "all okay" moments), auto-captured ctx snapshot (`MainForm.GetDiagnosticsContext` formats current state — area, date, target count, H/D/filter/Bortle/K), and the auto-captured MainForm screenshot path. Each session brackets between `USER_OBS_START id=<4-hex> build=<MinVer-sha>` (on open) and either `USER_OBS_END` (OK) or `USER_OBS_CANCEL` (Cancel/X). `grep id=4f2a tp.log` surfaces the START/END/CANCEL anchors; the DIAG lines between them bracket the investigation window by timestamp. Rotates `tp.log` → `tp.log.prev` and `screenshots/` → `screenshots.prev/` (older `.prev` is deleted first). Each run's diag trail + screenshots are self-contained; one session back preserved for postmortem. Writes `INFO new session` as the first line of the fresh `tp.log`.
